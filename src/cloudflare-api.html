Cloudflare API 使い方

管理用の REST API（api.cloudflare.com/client/v4）と GraphQL Analytics API を、API トークン・curl・cf CLI・SDK から使うときの決まりごと（2026 年 11 月時点）

ざっくり言うと
  • 設定の取得・変更は REST API、トラフィックなどの分析データの取得は GraphQL Analytics API で行う。
  • 認証は API トークンを Authorization: Bearer で送る。ユーザー用とアカウント用の 2 種類がある。
  • トークンは必要な権限・ゾーンだけに絞り、既定では無期限なので有効期限か IP 制限を付ける。

どの認証を使うか

自分のスクリプト・手元での作業ユーザー API トークンMy Profile で作る。作った人の権限の範囲で動く
CI/CD・監視などの長く動く連携アカウント API トークンManage Account で作る。作った人が抜けても動き続ける
Workers の開発（wrangler / cf）OAuth でログインwrangler login などでブラウザから。CI ではトークンを環境変数で渡す
どうしても必要な一部の API だけGlobal API Key旧来の方式で、ユーザーと同じ全権限。新しく使わない

認証情報の種類と接頭辞

2026 年から、新しく作る（またはロールする）認証情報は接頭辞付きの形式になった。接頭辞とチェックサムで、漏えいの検出ツールが見つけられる。

種類接頭辞送り方メモ
ユーザー API トークンcfut_Authorization: Bearer1 ユーザー 50 個まで
アカウント API トークンcfat_Authorization: Bearer1 アカウント 500 個まで。一部の製品は未対応
Global API Key（旧来）cfk_X-Auth-Email + X-Auth-Keyユーザーと同じ全権限。トークンに置き換える
Wrangler の OAuth トークンcfoat_（CLI が使う）wrangler login で発行される

それ以前に作ったものは接頭辞なし（トークンは英数字 40 文字、Global API Key は 16 進の小文字 37〜45 文字）で、そのまま使える。GitHub の Secret Scanning と連携していて、公開リポジトリに push された接頭辞付きトークンは自動で失効し、メールで知らせが来る。X-Auth-User-Service-Key の Service Key は 2026-09-30 で使えなくなった。

ユーザー用とアカウント用の違い

項目ユーザー API トークンアカウント API トークン
作る場所My Profile → API TokensManage Account → API Tokens
持ち主作ったユーザー。その人の権限の一部を受け継ぐアカウント（サービス用の主体）。作った人が組織を抜けても動く
作れる人そのユーザー本人Super Administrator か、トークンを発行できる権限を持つメンバー。自分の権限の範囲内でしか付けられない
向いている用途手元のスクリプト・その場の作業CI/CD・SIEM 連携など長く動くもの
確認 APIGET /user/tokens/verifyGET /accounts/{account_id}/tokens/verify

アカウント API トークンが使えない製品: Intel Data Platform・Page Rules・Registrar・Super Bot Fight Mode・Turnstile・Zero Trust Client Platform。これらはユーザー API トークンを使う。

API トークンを作る

  1. ゾーン ID・アカウント ID を控えるダッシュボードの各ドメインの概要ページで確認できる。API のパスに入れる
  2. 作成画面を開くユーザー用は My Profile → API Tokens、アカウント用は Manage Account → API Tokens で Create Token
  3. テンプレートを選ぶEdit zone DNS などのテンプレートか、一から作る（Custom Token）
  4. ポリシーを作る種類（Account・Zone・User）→ 権限名 → Read か Edit を選び、対象のアカウント・ゾーンを絞る。Edit は作成・取得・更新・削除・一覧、Read は取得・一覧
  5. 使える条件を絞るClient IP Address Filtering（CIDR で Is in / Is not in）と Token expiration（有効期間）。何もしないと、どの IP からでも、期限なしで使える
  6. 発行してすぐ保管Continue to summary → Create Token。値はこの画面でしか見られない
# 作ったトークンが有効か確かめる（"status": "active" なら OK）
curl https://api.cloudflare.com/client/v4/user/tokens/verify \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

# アカウント API トークンはこちら
curl https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/tokens/verify \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN"

トークン作成用のトークン（テンプレート「Create additional tokens」）を作れば、POST /user/tokens・POST /accounts/{account_id}/tokens で API からトークンを発行できる。強い権限なので、ほかの権限を付けず IP か期限で絞る。値が漏れたらロール（値の再発行）する。

REST と GraphQL

GitHub と違い、Cloudflare の GraphQL は分析データの読み取り専用。設定を変える操作はすべて REST で行う。

REST API

https://api.cloudflare.com/client/v4/…

  • DNS・キャッシュ・WAF・Workers・R2 など設定と管理のほぼ全部
  • レスポンスは決まった形の JSON（success・result など）
  • レート制限は 5 分 1,200 リクエスト
GET  /zones?name=example.com
POST /zones/{zone_id}/dns_records
POST /zones/{zone_id}/purge_cache

GraphQL Analytics API

POST https://api.cloudflare.com/client/v4/graphql

  • HTTP リクエスト・ファイアウォールのイベント・Workers の実行など 100 以上のデータセットを集計して読む（Limits のページでは「70 以上」）
  • 読み取りだけ（query のみで、mutation・subscription は無い）
  • 既定で 5 分に 300 クエリまで（API 全体の制限に加えてかかる）
query {
  viewer {
    zones(filter: {zoneTag: "…"}) {
      httpRequestsAdaptiveGroups(limit: 10, filter: {…}) { count }
    }
  }
}

以前の REST の分析エンドポイント（Zone Analytics など）からは、GraphQL へ移るよう移行ガイドが用意されている。

REST API を呼ぶ

export CLOUDFLARE_API_TOKEN=cfut_xxxxxxxx

# ドメイン名からゾーン ID を引く
ZONE_ID=$(curl -s "https://api.cloudflare.com/client/v4/zones?name=example.com" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" | jq -r '.result[0].id')

# DNS レコードの一覧（100 件ずつ、2 ページ目）
curl "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records?per_page=100&page=2" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" | jq .

# A レコードを作る（プロキシあり）
curl -X POST "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/dns_records" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"type":"A","name":"test","content":"192.0.2.1","proxied":true,"ttl":1}'

cf は 2026 年 9 月にベータで出た新しい CLI。OpenAPI のスキーマから生成した 2,900 以上のコマンドで、Cloudflare API のほぼ全体を扱える（Workers 専用の Wrangler とは別）。

npm i -g cf                      # cf と cloudflare の 2 つの名前で入る

cf zones list --name example.com
cf dns records list --zone example.com --type A
cf dns records create --zone example.com \
  --body '{"type":"A","name":"test","content":"192.0.2.1","proxied":true}'

cf cli search "purge cached files for a URL"   # やりたいことからコマンドを探す
cf schema zones create                         # 送る API リクエストの中身を見る
cf dns records delete <RECORD_ID> --zone <ZONE_ID> --dry-run   # 送らずに確認

出力は JSON なので jq に渡せる。ベータなので、コマンドや設定は正式版までに変わることがある。設定ファイル cloudflare.config.ts は「cf/config チートシート」を参照。

// TypeScript: npm install cloudflare
import Cloudflare from 'cloudflare';

const client = new Cloudflare({
  apiToken: process.env['CLOUDFLARE_API_TOKEN'],   // 既定でこの環境変数を読む
});

const zones = await client.zones.list({ name: 'example.com' });
const zoneId = zones.result[0].id;

// 自動でページを送りながら全件を回す
for await (const record of client.dns.records.list({ zone_id: zoneId })) {
  console.log(record.name, record.type);
}

Go（github.com/cloudflare/cloudflare-go）・Python（pip install cloudflare）もあり、どれも同じ OpenAPI スキーマから生成されていて client.dns.records.list(...) のように名前がそろっている。SDK はレート制限のヘッダーを読んで自動で待つ。

# 旧来の方式。ユーザーと同じ全権限になるので、新しくは使わない
curl https://api.cloudflare.com/client/v4/user \
  -H "X-Auth-Email: you@example.com" \
  -H "X-Auth-Key: $CLOUDFLARE_API_KEY"

ほとんどの操作は API トークンでできる。組織 (Organization) の読み取り・更新・削除など、Global API Key が必要な操作がごく一部残っている。漏れたら My Profile → API Tokens の API Keys から Change する。

REST のレスポンスとページ送り

{
  "success": true,            // 成否はまずここを見る
  "errors": [],               // 失敗時は [{"code": 10000, "message": "Authentication error"}] など
  "messages": [],
  "result": [ … ],            // 本体
  "result_info": { "page": 1, "per_page": 20, "count": 20, "total_count": 200, "total_pages": 10 }
}
  • 一覧は page と per_page で区切る。per_page を大きくしすぎるとタイムアウトすることがある
  • 並び順は order（並べる項目）と direction（asc・desc）。使えるパラメータはエンドポイントごとにリファレンスで確かめる
  • KV のキー一覧のように、cursor で続きを取るエンドポイントもある（result_info.cursor を次のリクエストに渡す）

よく使う REST エンドポイント

やりたいことメソッドとパストークンの権限
トークンの確認GET /user/tokens/verifyなし
アカウント一覧GET /accountsAccount Settings（読み取り）
ゾーン一覧・ゾーン ID を引くGET /zones?name=example.comZone（読み取り）
DNS レコード一覧GET /zones/{zone_id}/dns_recordsDNS（読み取り）
DNS レコードを作る・変える（書き込み）POST /zones/{zone_id}/dns_records・PATCH …/dns_records/{id}DNS（Edit）
キャッシュを消す（書き込み）POST /zones/{zone_id}/purge_cacheCache Purge（Purge）
Workers のスクリプト一覧GET /accounts/{account_id}/workers/scriptsWorkers Scripts（読み取り）
KV の名前空間一覧GET /accounts/{account_id}/storage/kv/namespacesWorkers KV Storage（読み取り）

# キャッシュを消す（URL 指定・全部）
curl -X POST "https://api.cloudflare.com/client/v4/zones/$ZONE_ID/purge_cache" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"files":["https://example.com/style.css"]}'      # 全部なら {"purge_everything":true}

全エンドポイントは API リファレンス（developers.cloudflare.com/api）にあり、各ページに必要な権限と curl・SDK の例が載っている。

GraphQL Analytics API を呼ぶ

  • トークンに分析の読み取り権限を付ける。ゾーンのデータ（HTTP リクエスト・ファイアウォールなど）は Zone → Analytics → Read、アカウントのデータ（Workers など）は Account → Account Analytics → Read
  • 入口は viewer → zones(filter: {zoneTag}) か accounts(filter: {accountTag}) → データセット。1 クエリでゾーンは 10 個、アカウントは 1 個まで
  • データセットごとに filter（さかのぼれる期間・1 回で取れる期間に上限があるので、期間を指定するのが基本）・limit・orderBy を付ける。集計結果は count・sum・avg と、グループ分けの dimensions
# 時間ごとのリクエスト数と転送量（ゾーン）
query Traffic($zoneTag: string, $start: Time, $end: Time) {
  viewer {
    zones(filter: { zoneTag: $zoneTag }) {
      httpRequestsAdaptiveGroups(
        limit: 100
        filter: { datetime_geq: $start, datetime_lt: $end }
        orderBy: [datetimeHour_ASC]
      ) {
        count
        sum { edgeResponseBytes }
        dimensions { datetimeHour }
      }
    }
  }
}

フィルタの演算子は名前の後ろに付ける（_gt・_lt・_geq・_leq・_neq・_in）。AND・OR も使える。

curl https://api.cloudflare.com/client/v4/graphql \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "query($zoneTag: string, $start: Time, $end: Time) { viewer { zones(filter: {zoneTag: $zoneTag}) { httpRequestsAdaptiveGroups(limit: 10, filter: {datetime_geq: $start, datetime_lt: $end}) { count } } } }",
    "variables": { "zoneTag": "'"$ZONE_ID"'", "start": "2026-11-27T00:00:00Z", "end": "2026-11-28T00:00:00Z" }
  }' | jq .

クエリの文字列は 1 行にする（改行を含めるならエスケープする）。長いクエリは GraphQL クライアントで組み立ててから貼る。

カーソルは無い。orderBy で並べ、最後に受け取った値より後ろをフィルタで指定して続きを取る（シーク方式）。並び順は細かく（複数の項目で）指定すると取りこぼしにくい。

# 1 回目
firewallEventsAdaptive(limit: 100, orderBy: [datetime_ASC, rayName_ASC],
  filter: { datetime_geq: $start }) { datetime rayName action }

# 2 回目以降: 前回の最後の datetime と rayName を使う
firewallEventsAdaptive(limit: 100, orderBy: [datetime_ASC, rayName_ASC],
  filter: { datetime_geq: $lastDatetime, rayName_gt: $lastRay }) { … }

データセットごとに、さかのぼれる期間・1 回で取れる期間・件数などの上限があり、プランで変わる。settings ノードで自分の上限を確かめられる。

query($zoneTag: string) {
  viewer {
    zones(filter: { zoneTag: $zoneTag }) {
      settings {
        firewallEventsAdaptive {
          enabled            # 使えるか
          notOlderThan       # 何秒前までさかのぼれるか
          maxDuration        # 1 回で指定できる期間（秒）
          maxPageSize        # 1 回で取れる件数
          maxNumberOfFields
        }
      }
    }
  }
}

GraphQL は失敗しても HTTP 200 で返ることがある。本文の errors が null でなければエラー（例: さかのぼれる期間を超えた）。複数のデータセットを 1 回で問い合わせて 1 つでも失敗すると、全体がエラーになる。

レート制限

対象上限
REST（ユーザー・アカウントのトークンごと）5 分に 1,200 リクエスト。ダッシュボード・API キー・トークンからのリクエストを合算
REST（IP アドレスごと）1 秒に 200 リクエスト
GraphQLクエリの重さで変わる。既定で 5 分に 300 クエリ（毎秒 1 回、または 300 回まとめて打って 5 分待つ。全体の Rate limits のページでは最大 320）。API 全体の制限に加えてかかる
個別の制限キャッシュの削除・Rulesets・Lists などは別に上限がある
ヘッダー（REST のみ）意味
Ratelimit残り回数 r と、枠が戻るまでの秒数 t（例: "default";r=50;t=30）
Ratelimit-Policy上限 q と枠の長さの秒数 w（例: "burst";q=100;w=60）
Retry-After上限を超えたとき（429）だけ付く。待つ秒数

上限を超えると、その後 5 分間はすべての API 呼び出しが 429 Too Many Requests になる。叩き続けず Retry-After の秒数だけ待つ。

エージェントから使う

Cloudflare API 全体を扱える公式の MCP サーバー（https://mcp.cloudflare.com/mcp）がある。2,500 以上のエンドポイントを search() と execute() の 2 つのツールに畳み込む「Code Mode」で、コンテキストを約 1,000 トークンしか使わない。コマンドで扱うなら、上の cf の cf cli search がエージェント向けに作られている。

よくある誤解

API トークンには自動で有効期限が付く

既定では無期限で、どの IP からでも使える。作成時に Token expiration と Client IP Address Filtering で絞る。

GraphQL API で設定も変えられる

Cloudflare の GraphQL は分析データの読み取り専用。DNS・キャッシュ・WAF などの設定は REST API（か cf・SDK・Terraform）で変える。

Global API Key のほうが手軽なので使ってよい

Global API Key はユーザーと同じ全権限を持ち、絞れない。ほとんどの操作は API トークンでできるので、必要な権限だけのトークンを使う。

アカウント API トークンなら作った人より強い権限を付けられる

メンバーが付けられるのは自分の権限の範囲内だけ。違いは、作った人が組織を抜けても動き続ける点。

429 になったらすぐ再試行すればよい

上限を超えると 5 分間すべての呼び出しが止められる。Retry-After を見て待つ。SDK は自動で待ってくれる。
