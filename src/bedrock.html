Amazon Bedrock 使い方

Converse API を中心に、モデル ID と推論プロファイル、認証、周辺機能（Knowledge Bases・Guardrails・バッチ・AgentCore）をまとめた早見表

ざっくり言うと
  • AWS のマネージドな生成 AI 基盤で、Claude・Amazon Nova・OpenAI などのモデルを同じ Converse API で呼べる。
  • 呼び出しは bedrock-runtime へ。新しいモデルは global.・jp. などの推論プロファイル ID で指定する。
  • モデルは既定で有効（Opus 4.7 より前の Claude だけ初回に利用フォームが要る）。エージェントの新規開発は AgentCore を使う。

エンドポイント（SDK のクライアント名）

クライアント役割主な操作
bedrock-runtime推論。新しいアプリはここを使うConverse・ConverseStream・InvokeModel・ApplyGuardrail、互換 API（/anthropic・/openai/v1）
bedrock管理（コントロールプレーン）モデル・推論プロファイルの一覧、Guardrails の作成、バッチジョブ、カスタムモデル
bedrock-agent-runtimeKnowledge Bases の検索Retrieve・RetrieveAndGenerate
bedrock-agentKnowledge Bases の管理ナレッジベース・データソースの作成、取り込み（ingestion）
bedrock-agentcore・bedrock-agentcore-controlAgentCore（エージェント基盤）Runtime・Memory・Gateway などの呼び出しと管理
bedrock-mantleOpenAI 互換 API の別エンドポイント引き続き使えるが、新規は bedrock-runtime が推奨（2026-08 から）。Web Search・Projects など mantle だけの機能もある

使い始める

  1. IAM の権限試すなら AmazonBedrockLimitedAccess か AmazonBedrockFullAccess。本番は bedrock:InvokeModel・bedrock:InvokeModelWithResponseStream（Converse・ConverseStream もこの権限で呼ぶ）を、対象のモデルとプロファイルに絞る
  2. モデルアクセスサーバーレスのモデルは 2025-10 から既定で有効（手動の有効化ページは不要）。AWS Marketplace 経由のモデルは、Marketplace の権限を持つ人が最初に 1 回呼ぶとアカウントで購読される
  3. 古い Claude だけ追加の手順Claude Opus 4.7 より前のモデル（Sonnet 4.6・Haiku 4.5 など）は、初回に First Time Use フォーム（会社名・Web サイト・用途など）を出す。コンソールでモデルを選ぶか PutUseCaseForModelAccess API。組織の管理アカウントで出せばメンバーアカウントにも効く。Opus 4.7 以降と bedrock-mantle 経由では不要
  4. 認証通常の AWS 認証情報（SigV4）か、Bedrock の API キー（下の表）
API キー有効期間向いている場面
短期キー発行したセッションの残り時間（最長 12 時間）本番・CI。aws-bedrock-token-generator（Python・JS・Java）で自動更新できる
長期キー発行時に決めた期限まで（IAM ユーザーに紐づく）試すときだけ。本番には使わない
 
export AWS_BEARER_TOKEN_BEDROCK=発行したキー   # SDK・CLI がこの変数を読む
# curl なら Authorization: Bearer $AWS_BEARER_TOKEN_BEDROCK

モデル ID と推論プロファイル

新しいモデルの多くは、モデル ID を直接指定できず（inferenceTypesSupported が INFERENCE_PROFILE だけ）、推論プロファイル ID を modelId に渡す。プロファイルはリクエストを複数のリージョンに振り分ける（クロスリージョン推論）。

指定のしかた例（Claude Opus 5.5）処理されるリージョン
モデル IDanthropic.claude-opus-5-5呼んだリージョンだけ（対応するモデルのみ）
地域のプロファイルjp.anthropic.claude-opus-5-5（ほかに us.・eu.・au. など）その地域の中だけ（jp. は東京・大阪）。データの置き場所を地域内に留めたいとき。モデルによっては無い（モデルカードで確かめる）
グローバルのプロファイルglobal.anthropic.claude-opus-5-5世界中の対応リージョン。混雑に強い
アプリケーション推論プロファイル自分で作った ARN元のプロファイルと同じ。コスト配分タグを付けて用途ごとに集計する
 
aws bedrock list-foundation-models --by-provider anthropic --region ap-northeast-1 \
  --query 'modelSummaries[].[modelId,inferenceTypesSupported]' --output table
aws bedrock list-inference-profiles --region ap-northeast-1 \
  --query 'inferenceProfileSummaries[].inferenceProfileId' --output text

モデルを呼ぶ

import boto3

brt = boto3.client("bedrock-runtime", region_name="ap-northeast-1")
MODEL = "jp.anthropic.claude-opus-5-5"

res = brt.converse(
    modelId=MODEL,
    system=[{"text": "日本語で簡潔に答える"}],
    messages=[{"role": "user", "content": [{"text": "LEFT JOIN を一文で"}]}],
    inferenceConfig={"maxTokens": 1024, "temperature": 0.2},
)
print(res["output"]["message"]["content"][0]["text"])
print(res["usage"], res["stopReason"])   # トークン数・止まった理由

# ストリーミング
stream = brt.converse_stream(modelId=MODEL, messages=[{"role": "user", "content": [{"text": "短い物語を"}]}])
for ev in stream["stream"]:
    if "contentBlockDelta" in ev:
        print(ev["contentBlockDelta"]["delta"].get("text", ""), end="")

会話を続けるときは、返ってきた res["output"]["message"] を messages に足して次の user を送る（サーバーは履歴を持たない）。

aws bedrock-runtime converse \
  --region ap-northeast-1 \
  --model-id jp.anthropic.claude-opus-5-5 \
  --messages '[{"role":"user","content":[{"text":"こんにちは"}]}]' \
  --inference-config '{"maxTokens":512}' \
  --query 'output.message.content[0].text' --output text
# Anthropic Messages API 互換（bedrock-runtime の /anthropic）
# pip install anthropic aws-bedrock-token-generator
from anthropic import Anthropic
from aws_bedrock_token_generator import provide_token

client = Anthropic(
    base_url="https://bedrock-runtime.us-east-1.amazonaws.com/anthropic",
    api_key=provide_token(region="us-east-1"),     # 短期の API キー
)
msg = client.messages.create(
    model="global.anthropic.claude-opus-5-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "こんにちは"}],
)
print(msg.content[0].text)

SigV4 で呼ぶ従来の AnthropicBedrock クライアント（pip install "anthropic[bedrock]"）も使える。

# OpenAI 互換（Chat Completions・Responses）。bedrock-runtime の /openai/v1
from openai import OpenAI
import os

client = OpenAI(
    base_url="https://bedrock-runtime.us-east-1.amazonaws.com/openai/v1",
    api_key=os.environ["AWS_BEARER_TOKEN_BEDROCK"],
)
res = client.chat.completions.create(
    model="モデルカードに書かれた ID",
    messages=[{"role": "user", "content": "こんにちは"}],
)
print(res.choices[0].message.content)

どのモデルがどの互換 API に対応するかは、各モデルカードの「エンドポイント」の表で確かめる。

Converse と InvokeModel

Converse / ConverseStreamInvokeModel / InvokeModelWithResponseStream
本文の形全モデル共通（messages・system・inferenceConfig・toolConfig）モデルごとのネイティブの JSON
モデルの差し替えmodelId を変えるだけ本文と応答の解析も書き直す
使えないもの埋め込み・画像生成のモデル—（全モデル対応）
モデル固有の引数additionalModelRequestFields に入れる本文にそのまま書く

Converse の主なパラメータ

キー用途
inferenceConfigmaxTokens・temperature・topP・stopSequences
toolConfigツール定義（tools[].toolSpec に name・description・inputSchema.json）。応答の stopReason が tool_use なら実行して toolResult を返す
{"cachePoint": {"type": "default"}}プロンプトキャッシュの区切り。system・messages・tools の中に置く（対応モデルのみ）
guardrailConfigGuardrail の ID とバージョンを付けて入出力を検査
serviceTier{"type": "priority" | "default" | "flex" | "reserved"}（下のサービス階層）
requestMetadata呼び出しログに残すキーと値（用途別の集計）
additionalModelRequestFields思考の設定などモデル固有の引数

周辺機能

機能何をするか使い方の入口
Knowledge BasesS3 などの文書を取り込んでベクトル化し、RAG の検索をマネージドで行うbedrock-agent-runtime の retrieve（検索だけ）・retrieve_and_generate（回答まで）
Guardrails有害な内容・話題・個人情報・プロンプト攻撃のフィルタ、根拠との照合Converse の guardrailConfig、単体なら apply_guardrail（Bedrock 外のモデルの出力にも使える）
バッチ推論S3 の JSONL をまとめて処理。オンデマンドより安いaws bedrock create-model-invocation-job。入力は Converse の形式でもよい（2026-02 から）。既定の期限は 24 時間（最長 168 時間）
サービス階層リクエストごとに速さと料金を選ぶpriority（割増で速い）・default（Standard）・flex（割安・遅くてよい）・reserved（事前予約）
呼び出しログ入出力とメタデータを CloudWatch Logs・S3 に記録コンソールの「Settings」→ Model invocation logging（既定は無効）
Prompt Management・Flowsプロンプトのバージョン管理、ノードをつないだワークフローコンソールか bedrock-agent の API
 
# Knowledge Bases で検索して回答まで
kb = boto3.client("bedrock-agent-runtime", region_name="ap-northeast-1")
res = kb.retrieve_and_generate(
    input={"text": "返品の期限は？"},
    retrieveAndGenerateConfiguration={
        "type": "KNOWLEDGE_BASE",
        "knowledgeBaseConfiguration": {
            "knowledgeBaseId": "KBID1234",
            "modelArn": "推論プロファイルの ARN",
        },
    },
)
print(res["output"]["text"])
for c in res["citations"]:                      # 根拠になった文書
    print([r["location"] for r in c["retrievedReferences"]])

エージェント（AgentCore）

Bedrock Agents（今は Agents Classic と呼ぶ）は 2026-07-30 から新規の顧客を受け付けていない。新しく作るなら AgentCore を使う。AgentCore はフレームワーク（Strands Agents・LangGraph・CrewAI など）もモデルも選ばず、必要な部品だけを使える。

部品何をするか
Runtimeエージェント・ツールのコードをサーバーレスで動かす。セッションごとに分離された microVM
Memory会話の短期記憶と、セッションをまたぐ長期記憶
GatewayAPI・Lambda などを MCP のツールとしてエージェントに公開する
Identityエージェントの ID と、外部サービスへの OAuth トークンの保管
Code Interpreter・Browser隔離された環境でのコード実行、クラウドのブラウザ操作
Observability・Evaluations・PolicyCloudWatch・OpenTelemetry での追跡、品質の評価、ツール呼び出しの許可ルール

よくある誤解

使う前にコンソールのモデルアクセスのページで、モデルを 1 つずつ有効にする必要がある

2025-10 から、サーバーレスのモデルは商用リージョンで既定で使える。残る手順は、Opus 4.7 より前の Claude の初回フォームと、AWS Marketplace 経由のモデルを最初に呼ぶ人の Marketplace 権限だけ。アクセス拒否のときは IAM と SCP を見る。

modelId には anthropic.claude-… のモデル ID をそのまま書けばよい

新しい Claude などは推論プロファイル経由でしか呼べず、モデル ID を直接渡すとエラーになる。jp.・us.・global. などを付けたプロファイル ID を使う。IAM ポリシーではプロファイルと、振り分け先リージョンのモデルの両方を許可する。

Converse API はどのモデルにも使える

埋め込みと画像生成のモデルは Converse に対応していないので、InvokeModel でそのモデルのネイティブの形式で呼ぶ。

エージェントを作るなら Bedrock Agents を使う

Bedrock Agents（Agents Classic）は 2026-07-30 から新規の顧客を受け付けていない（既存の利用者はそのまま使える）。新しく作るなら AgentCore と、好きなフレームワークを組み合わせる。
