sqlc 使い方

書いた SQL から型付きの Go コードを生成するツール。PostgreSQL・MySQL・SQLite に対応（v1.31 時点）

ざっくり言うと
  • sqlc は、スキーマ（DDL）とクエリの SQL を読んで、型付きの Go の関数と構造体を生成するコード生成ツール。
  • クエリに -- name: GetUser :one と名前と戻り方を書くと、q.GetUser(ctx, id) が生える。
  • ORM ではないので SQL はそのまま書く。動的な条件の組み立ては苦手で、マイグレーションも別のツールで行う。

生成の流れ

schema.sqlCREATE TABLE（マイグレーションのフォルダでもよい）
query.sql-- name: 付きのクエリ
sqlc generatesqlc.yaml に従って解析
生成コードdb.go・models.go・query.sql.go

インストール

brew install sqlc
go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest
docker run --rm -v $(pwd):/src -w /src sqlc/sqlc generate

sqlc.yaml

version: "2"
sql:
  - engine: "postgresql"        # postgresql / mysql / sqlite
    schema: "db/migrations"     # ファイルでもフォルダでもよい
    queries: "db/queries"
    gen:
      go:
        package: "db"
        out: "internal/db"
        sql_package: "pgx/v5"   # 既定は database/sql
        emit_json_tags: true
        emit_interface: true    # Querier インターフェースも出す（モック用）
        overrides:
          - db_type: "uuid"
            go_type:
              import: "github.com/google/uuid"
              type: "UUID"
キー（gen.go の下）意味
sql_packagedatabase/sql（既定）・pgx/v5・pgx/v4
emit_json_tags・json_tags_case_style構造体に json:"…" を付ける・その表記（camel・snake など）
emit_interfaceQuerier インターフェースを出す
emit_empty_slices:many が 0 件のとき nil ではなく空のスライスを返す
emit_pointers_for_null_typesNULL になる列を *string などにする（PostgreSQL + pgx と SQLite のみ。既定は sql.NullString・pgtype.Text）
emit_prepared_queriesプリペアドステートメントを使う Prepare を出す
query_parameter_limit引数がこの数を超えたら Params 構造体にまとめる（既定 1）
overridesDB の型（db_type）か列（column: "users.id"）ごとに Go の型を差し替える
rename生成される名前を変える（rename: { "uid": "UserID" }）

overrides の db_type は NULL 可かどうかで別扱い。両方を差し替えるなら nullable: true 付きともう 1 つの 2 行を書く。

クエリの書き方（注釈）

-- name: GetAuthor :one
SELECT * FROM authors WHERE id = $1 LIMIT 1;

-- name: ListAuthors :many
SELECT * FROM authors ORDER BY name;

-- name: CreateAuthor :one
INSERT INTO authors (name, bio) VALUES ($1, $2) RETURNING *;

-- name: DeleteAuthor :exec
DELETE FROM authors WHERE id = $1;
注釈生成される関数の戻り値
:one1 行（(Author, error)）。0 件なら sql.ErrNoRows（pgx は pgx.ErrNoRows）
:many複数行（([]Author, error)）
:execerror だけ
:execrows影響した行数（(int64, error)）
:execresultsql.Result（pgx では pgconn.CommandTag）
:execlastid最後に挿入した ID（LastInsertId。MySQL・SQLite 向け）
:copyfrom大量 INSERT（PostgreSQL の COPY・MySQL の LOAD DATA）。PostgreSQL は sql_package: pgx/v5（か v4）、MySQL は sql_driver: github.com/go-sql-driver/mysql も必要
:batchexec・:batchmany・:batchonepgx のバッチ送信（PostgreSQL + pgx のみ）

マクロ

マクロ用途
sqlc.arg(name)・@name引数に名前を付ける（$1 の代わり。略記の @name は MySQL では使えない）
sqlc.narg(name)NULL を渡せる引数にする（任意の検索条件など）
sqlc.slice(ids)IN (…) にスライスを渡す（MySQL・SQLite。PostgreSQL は = ANY($1::int[])）
sqlc.embed(users)JOIN の結果に既存のモデル構造体を丸ごと埋め込む
 
-- name: SearchAuthors :many
SELECT * FROM authors
WHERE (sqlc.narg(name)::text IS NULL OR name ILIKE sqlc.narg(name))
  AND created_at >= @since
ORDER BY id;

コマンド

コマンド用途
sqlc init空の sqlc.yaml を作る
sqlc generateコードを生成する
sqlc compile生成せずに SQL の文法と型だけを確かめる
sqlc diff生成結果と今のファイルが違えば失敗（CI で「generate し忘れ」を検出）
sqlc vetrules に CEL で書いた独自ルールでクエリを検査
sqlc parseSQL の AST を JSON で出力する（v1.31 で追加。sqlc fmt・sqlc analyze は main ブランチにあるが v1.31.1 時点では未リリース）
-f path/sqlc.yaml設定ファイルを指定する（CLI のドキュメントに載っている --no-database は今の版には実装されていない）

マイグレーションとの組み合わせ

sqlc はスキーマを変更しない。schema にマイグレーションのフォルダを指定すると、ファイル名の順に読んで最終的な形を組み立てる。対応しているツールの形式: atlas・dbmate・golang-migrate・goose・sql-migrate・tern。ダウン側（-- +goose Down など）は無視される。

MySQL で「CREATE 文を正として差分を当てる」宣言型の管理をするなら Skeema と組み合わせ、schema に Skeema のフォルダを指定する、という使い方もできる。

導入の手順

  1. 設定を作るsqlc init のあと、エンジン・スキーマ・クエリ・出力先を書く
  2. クエリを書く-- name: 名前 :注釈 を付けて、1 ファイルに機能ごとのクエリをまとめる
  3. 生成するsqlc generate。生成物はコミットし、go generate から呼んでもよい
  4. CI で確かめるsqlc diff と sqlc vet を流し、生成し忘れと危ないクエリを止める

よくある誤解

sqlc は ORM の一種で、マイグレーションも面倒を見てくれる

sqlc はコードを生成するだけで、実行時には何もしない。スキーマの変更は golang-migrate・goose・Atlas・Skeema など別のツールで行い、sqlc はその結果のスキーマを読むだけ。

条件を足し引きする動的なクエリも sqlc で自由に組み立てられる

生成されるのは書いたとおりの固定の SQL。任意の条件は sqlc.narg と IS NULL OR … で表すのが基本で、並び替えの列を変えるなどの大きな組み立ては、その部分だけ手書きやクエリビルダーにする。

SELECT * と書くと、実行時に列が増えても自動で追従する

* は生成時に列名へ展開されて固定される。スキーマを変えたら sqlc generate をやり直す（CI の sqlc diff で検出できる）。

関連: Go のコードでスキーマを書く方式は ent 使い方。
