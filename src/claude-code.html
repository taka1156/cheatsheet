Claude Code 拡張機能 使い方

CLAUDE.md・スキル・サブエージェント・フック・MCP・プラグイン・権限を、置き場所と書き方で引く

ざっくり言うと
  • Claude Code は .claude/（プロジェクト）と ~/.claude/（個人）に置いたファイルで振る舞いを足せる。
  • 事実・規約は CLAUDE.md、手順はスキル、別コンテキストでの作業はサブエージェント、必ず実行したい処理はフックに書く。
  • CLAUDE.md やスキルは Claude への「お願い」で、確実に止めたい操作はフックか権限の deny で止める。

どれを使うか

あなたが起動する

/スキル名・@"名前 (agent)"・/コマンド

Claude が判断して使う

スキル（description を見て読み込む）・サブエージェント（description を見て委譲）・MCP ツール

イベントで必ず動く

フック（ツール実行の前後・セッション開始・応答終了など）。Claude の判断を通さない

機能置き場所（プロジェクト／個人）読み込まれ方向いている用途
CLAUDE.md./CLAUDE.md／~/.claude/CLAUDE.md毎セッション全文ビルド・テストのコマンド、コーディング規約などの事実
ルール.claude/rules/*.md／~/.claude/rules/paths 指定なしは毎回、ありは該当ファイルを扱うときだけ特定のディレクトリ・拡張子だけの規約
スキル.claude/skills/<名前>/SKILL.md／~/.claude/skills/description だけ常に。本文は使うときだけデプロイ・レビューなど繰り返す手順、/ コマンド
サブエージェント.claude/agents/*.md／~/.claude/agents/委譲したときだけ、別のコンテキストで動く調査・レビューなど、結果だけ欲しい作業。ツールやモデルを絞りたいとき
フック.claude/settings.json の hooks／~/.claude/settings.jsonイベントが起きるたびに実行編集後の整形、危険なコマンドの拒否、通知
MCP.mcp.json／~/.claude.jsonツールとして常に使えるGitHub・DB・社内 API などの外部ツール
プラグインマーケットプレイスからインストール有効にした範囲で、中身の各機能として上のものを束ねてチームや他のプロジェクトに配る

ファイルの置き場所

your-project/
├── CLAUDE.md               # プロジェクトの指示（.claude/CLAUDE.md でもよい）
├── CLAUDE.local.md         # 自分だけの指示（.gitignore に入れる）
├── .mcp.json               # プロジェクト共有の MCP サーバー
└── .claude/
    ├── settings.json       # チーム共有の設定（権限・フック・プラグイン・env）
    ├── settings.local.json # 自分だけの設定（git から外す）
    ├── rules/*.md          # 分割した指示。paths で対象ファイルを絞れる
    ├── skills/<名前>/SKILL.md
    ├── agents/<名前>.md
    └── commands/<名前>.md   # 旧形式のカスタムコマンド（今も動く）

~/.claude/
├── CLAUDE.md  rules/  skills/  agents/  settings.json   # 全プロジェクト共通
└── projects/<project>/memory/MEMORY.md                 # 自動メモリ（Claude が書く）
~/.claude.json              # MCP（local・user スコープ）・アカウントなど。手で触らない

CLAUDE.md とルール

ファイル場所誰に効くか
組織のポリシーmacOS /Library/Application Support/ClaudeCode/CLAUDE.md・Linux /etc/claude-code/CLAUDE.md組織の全員
ユーザー~/.claude/CLAUDE.md自分（全プロジェクト）
プロジェクト./CLAUDE.md か ./.claude/CLAUDE.mdリポジトリを使う全員
ローカル./CLAUDE.local.md自分（このプロジェクト）
  • 起動したディレクトリとその上の階層の CLAUDE.md は起動時に全部読まれ、上書きではなく連結される（近いものほど後）。サブディレクトリの CLAUDE.md は、Claude がそこのファイルを触ったときに読まれる。
  • @path/to/file で別ファイルを取り込める（相対パスは書いたファイルから。入れ子は 4 段まで）。バッククォートで囲めば取り込まれない。
  • 1 ファイル 200 行以内が目安。/init でコードベースから下書きを作れる。CLAUDE.md が無く AGENTS.md があれば、そちらを読む。
  • 自動メモリ: Claude が自分で ~/.claude/projects/<project>/memory/ にメモを書く。MEMORY.md の先頭 200 行（または 25KB）が毎回読まれる。オン・オフは /memory。

スキル（SKILL.md）

フォルダ名が /コマンド名 になる。.claude/commands/deploy.md と .claude/skills/deploy/SKILL.md はどちらも /deploy を作る（カスタムコマンドはスキルに統合された）。同名なら企業 > 個人 > プロジェクトの順で優先。プラグインのスキルは /プラグイン名:スキル名。

~/.claude/skills/summarize-changes/SKILL.md
---
description: 未コミットの変更を要約し危険な点を挙げる。変更点やコミットメッセージを聞かれたときに使う。
allowed-tools: Bash(git diff *)
---
## 今の変更
!`git diff HEAD`

## 指示
上の変更を 2〜3 点に要約し、リスクを挙げる。
キー意味
name/ メニューの名前。省略時はフォルダ名
description何をするか・いつ使うか。Claude はこれで読み込むかを決める（when_to_use と合わせて 1,536 字で切られる）
argument-hint補完に出す引数のヒント（例: [issue-number]）
arguments名前付き引数。$name で参照
disable-model-invocationtrue で自分の /名前 だけが起動できる
user-invocablefalse で / メニューから隠し、Claude だけが使う
allowed-toolsそのターンの間、確認なしで使えるツール
disallowed-toolsスキルが有効な間、使えなくするツール
model・effortそのターンのモデル・effort（low〜max）
context: fork・agentフォークしたサブエージェントで実行。agent で種類（Explore など）を指定
paths自動で読み込む対象ファイルを glob で絞る
hooksスキルを起動したときに登録するフック
書き方展開されるもの
$ARGUMENTS引数全体
$0・$1…（$ARGUMENTS[N]）0 始まりの N 番目の引数。空白を含む値は "…" で囲む
$namearguments で名前を付けた引数
${CLAUDE_SKILL_DIR}SKILL.md のあるフォルダ（同梱スクリプトの参照に）
${CLAUDE_PROJECT_DIR}・${CLAUDE_SESSION_ID}プロジェクトのルート・セッション ID
!`コマンド`Claude が読む前にシェルで実行し、出力に置き換える。失敗するとスキル全体が止まるので、失敗しうるものは || true

どこにも引数の置き場が無いと、本文の末尾に ARGUMENTS: 値 が足される。$1 のように引数として置き換えられる形をそのまま残したいときは、\$1.00 のように \ を前に付ける（ほかの $ の前の \ はそのまま残る）。

設定自分が起動Claude が起動description がコンテキストに
（既定）できるできる常に入る
disable-model-invocation: trueできるできない入らない
user-invocable: falseできないできる常に入る

デプロイのように勝手に走られると困る手順は disable-model-invocation: true にする。

SKILL.md は 500 行以内にし、詳細は同じフォルダの reference.md や scripts/ に分けて本文から参照する。一覧は /skills。同梱スキルには /doctor・/code-review・/debug・/batch・/loop などがある。

サブエージェント

自分専用のコンテキストで動く別の Claude。調査の途中経過でメインの会話を埋めずに、結果だけを返させられる。ツール・モデル・権限を絞れる。

.claude/agents/code-reviewer.md
---
name: code-reviewer
description: コードの品質をレビューする。コードを変更したあとに積極的に使う。
tools: Read, Glob, Grep
model: sonnet
---
あなたはコードレビュアーです。品質・セキュリティ・ベストプラクティスの観点で、具体的な指摘を返してください。
キー意味
name・description必須。description を見て Claude が委譲するかを決める
tools・disallowedTools使えるツールの許可リスト・拒否リスト。tools を省くと使えるツールを全部引き継ぐ
modelsonnet・opus・haiku・モデル ID・inherit
permissionModedefault・acceptEdits・auto・dontAsk・bypassPermissions・plan
skills・mcpServers起動時に全文を読み込むスキル・使わせる MCP サーバー
maxTurns・effort最大ターン数・effort
isolation: worktree一時的な git worktree の中で動かす
memoryサブエージェント自身の永続メモリ（user・project・local）
hooks・colorこのサブエージェントだけのフック・表示色
呼び出し方書き方
自然文で頼むcode-reviewer サブエージェントで最近の変更を見て
@ メンション（確実に使わせる）@"code-reviewer (agent)" 認証まわりを見て
セッション全体をそのエージェントにclaude --agent code-reviewer（既定にするなら設定の "agent"）
そのセッションだけ定義するclaude --agents '{"名前": {"description": "…", "prompt": "…"}}'

組み込みは Explore（読み取り専用の調査）・Plan（プランモードの調査）・general-purpose など。同名ならマネージド設定 > --agents > .claude/agents/ > ~/.claude/agents/ > プラグインの順で優先。サブエージェントは既定でメインから 3 段下までサブエージェントを起動できる（CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH で変更）。

フック

決まったタイミングで必ず動く、シェルコマンド・HTTP・プロンプトなどの処理。settings.json の hooks に「イベント → matcher → 処理」の 3 段で書く（プラグインの hooks/hooks.json、スキル・サブエージェントのフロントマターにも書ける）。登録済みのフックは /hooks で見られる。

イベントいつ止められるかmatcher で絞るもの
SessionStartセッションの開始・再開いいえstartup|resume|clear|compact|fork
UserPromptSubmitプロンプト送信後、Claude が処理する前はい—
PreToolUseツールを実行する前はいツール名
PermissionRequest権限の確認が必要になったときJSON の decision で許可・拒否ツール名
PostToolUseツールが成功したあといいえ（理由を Claude に返せる）ツール名
Notification入力待ち・権限待ちなどの通知いいえ通知の種類
StopClaude が応答を終えたときはい（続けさせる）—
SubagentStart・SubagentStopサブエージェントの開始・終了Stop のみ はいエージェントの種類
PreCompact・PostCompactコンテキスト圧縮の前後Pre のみ はいmanual|auto
ConfigChange・FileChanged設定ファイル・監視中のファイルが変わったときConfigChange のみ はい設定の種類・ファイル名
SessionEndセッションの終了いいえ—

ほかに PostToolUseFailure・TaskCreated・InstructionsLoaded・CwdChanged・WorktreeCreate・Elicitation などがある（全一覧は参考の Hooks reference）。

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
項目書き方
matcher省略・"*" で全部。英数字・_・-・空白・,・| だけなら完全一致のリスト（Edit|Write）。それ以外の文字を含むと、前後を固定しない正規表現になる（mcp__github__.*。全体一致は ^…$）
if権限ルールの書き方でさらに絞る（ツールのイベントだけ。Bash(git *)・Edit(*.ts)）
typecommand（stdin に JSON）・http（JSON を POST）・mcp_tool・prompt（LLM で判定）・agent（実験的）
timeout秒。command などは既定 600 秒
asynctrue で裏で実行して待たない（ログ・通知向け）

スクリプトは chmod +x しておく。プロジェクトのスクリプトは ${CLAUDE_PROJECT_DIR}、プラグインのものは ${CLAUDE_PLUGIN_ROOT} から書く。stdin の JSON には session_id・cwd・hook_event_name、ツールのイベントなら tool_name・tool_input が入る。

終了コード意味
0成功。stdout が JSON なら読み取る。UserPromptSubmit・SessionStart ではプレーンテキストの stdout がコンテキストに入る
2ブロック。stderr が理由として Claude に渡り、止められるイベントなら操作が止まる
それ以外（1 など）止まらないエラー。操作はそのまま進み、エラーの通知だけ出る
JSON（stdout）効果
"continue": false ＋ stopReasonClaude をまるごと止める
"decision": "block" ＋ reasonUserPromptSubmit・PostToolUse・Stop などで止める・やり直させる
hookSpecificOutput.permissionDecisionPreToolUse で allow・deny・ask・defer。updatedInput で入力を書き換えられる
hookSpecificOutput.additionalContextClaude に文脈を足す（PostToolUse・SessionStart など）
systemMessageユーザーに警告を表示する

編集したファイルを Prettier で整形する（PostToolUse）

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }
        ]
      }
    ]
  }
}

rm -rf を止める（PreToolUse のスクリプト。exit 2 でブロック）

#!/bin/bash
cmd=$(jq -r '.tool_input.command')
if echo "$cmd" | grep -q 'rm -rf'; then
  echo "rm -rf は禁止です" >&2
  exit 2
fi
exit 0

# ローカル（stdio）: オプションは名前の前、サーバーのコマンドは -- の後

  -- npx -y airtable-mcp-server

claude mcp list | get <名前> | remove <名前>
スコープ（--scope）使える範囲保存先
local（既定）このプロジェクト・自分だけ~/.claude.json
projectこのプロジェクト・チームで共有.mcp.json
user自分の全プロジェクト~/.claude.json

{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",

${VAR}・${VAR:-既定値} は環境変数で展開される。接続状態の確認・OAuth の認証はセッション内の /mcp。MCP のツール名は mcp__サーバー名__ツール名 になり、フックの matcher や権限ルールでもこの名前を使う。

プラグイン

スキル・サブエージェント・フック・MCP サーバーを 1 つのフォルダに束ねて配る仕組み。公式マーケットプレイス（claude-plugins-official）は初回起動時に自動で登録される。それ以外のマーケットプレイス（プラグインの一覧を載せたリポジトリ）は登録してからインストールする。

/plugin                                              # メニューで探す・管理
/plugin marketplace add <owner>/<repo>               # 公式以外のマーケットプレイスを登録
/plugin install github@claude-plugins-official       # <プラグイン>@<マーケットプレイス>
/reload-plugins                                      # 変更を再起動なしで反映
claude --plugin-dir ./my-plugin                      # 開発中のものを直接読み込む
my-plugin/
├── .claude-plugin/plugin.json   # {"name": "my-plugin", "description": "…", "version": "1.0.0"}
├── skills/<名前>/SKILL.md
├── agents/<名前>.md
├── hooks/hooks.json
└── .mcp.json

自分でマーケットプレイスを作るときは、リポジトリのルートに .claude-plugin/marketplace.json（name・owner・plugins が必須）を置く。チームに配るなら .claude/settings.json の extraKnownMarketplaces・enabledPlugins に書く。

設定と権限

同じキーは上ほど優先（配列の permissions.allow などは上書きでなく結合）。/status の Setting sources で、読み込まれたファイルを確かめられる。

  1. マネージド設定組織が配る。ユーザー・プロジェクト・--settings からは原則上書きできない（一部のセキュリティ系キーは、より厳しい値なら下位の設定も効く）
  2. コマンドラインclaude --settings '{"model": "…"}'。そのセッションだけ
  3. .claude/settings.local.json自分だけ・このプロジェクトだけ。「今後は聞かない」を選ぶとここに allow が書かれる
  4. .claude/settings.jsonチーム共有。コミットする
  5. ~/.claude/settings.json自分の全プロジェクト
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "ask":   ["Bash(git push *)"],
    "deny":  ["Read(./.env)", "Read(./.env.*)"]
  }
}
ルール当てはまるもの
Bash(npm run build)そのコマンドだけ（--watch 付きは別）
Bash(npm run *)npm run で始まるもの全部（npm run 単体も）
Bash(ls *) と Bash(ls*)空白ありは lsof に当たらない。空白なしは当たる
Read(./.env)・Edit(…)ファイルのパス
WebFetch(domain:example.com)そのドメインへの取得
mcp__github__*github サーバーのツール全部

評価は deny → ask → allow の順で、最初に当たったものに決まる（具体的なルールが優先されるわけではない）。&&・| などでつないだコマンドは、1 つずつ照合される。対話でルールを編集するなら /permissions。

権限モード動き
default（Manual）ツールの初回使用ごとに確認する
acceptEdits作業ディレクトリ内のファイル編集と mkdir・mv などを自動で許可
plan読むだけで計画を立てる。ソースは編集しない（/plan で入る）
auto確認なしで進め、裏の分類器が依頼に合う操作か確かめる
dontAsk確認が必要なものは全部自動で拒否（allow 済みだけ動く）
bypassPermissions確認を省く。隔離した環境向け

起動時に --permission-mode で指定でき、既定は permissions.defaultMode。auto・bypassPermissions はプロジェクトの設定ファイルからは効かない（ユーザー設定かマネージド設定に書く）。

よくある誤解

CLAUDE.md に「〇〇しない」と書けば必ず守られる

CLAUDE.md は文脈として読まれるだけで、強制力はない。確実に止めたい操作は、PreToolUse のフック（exit 2）か、権限の deny ルールで止める。

フックのスクリプトは exit 1 で失敗させれば操作が止まる

既定で止めるのは exit 2 だけ。exit 1 などは「止まらないエラー」で、操作はそのまま進む。失敗やタイムアウトでも止めたいときは、フックに "onFailure": "block" を付ける。

具体的な allow ルールを書けば、広い deny ルールの例外にできる

評価は deny → ask → allow の順で、具体性は関係ない。Bash(aws *) を deny にすると、Bash(aws s3 ls) を allow にしても止まる。

スキルができたので .claude/commands/ のファイルは動かなくなった

今も動く。.claude/commands/deploy.md も /deploy になる。補助ファイルや起動の制御が要るときだけスキルの形に移せばよい。

サブエージェントの中からはサブエージェントを呼べない

既定ではメインの会話から 3 段下まで呼べる。止めたいサブエージェントは tools から Agent を外すか、disallowedTools に入れる。
