Cloudflare Radar 使い方

インターネット全体のトラフィック・攻撃・経路・脆弱性を Cloudflare の観測データで見る無料のハブ。画面・CVE ページ・URL Scanner・API・通知・AI 連携をまとめる（2026-11 時点）

ざっくり言うと
  • Radar は Cloudflare のネットワークと 1.1.1.1 の集計データで、ネット全体の通信・攻撃・経路を見せる無料サイト。
  • 画面で見る・URL Scanner で怪しい URL を調べる・API で取り出す・通知で受け取る、の 4 通りで使う。
  • 見えるのは Cloudflare から観測した割合や傾向で、絶対量や自社サイトの状況ではない点に注意する。

CVE ページ（Zero Wire）

公開済みのすべての CVE に 1 ページずつあり、深刻度・悪用状況・影響製品・対処を NVD・CISA・FIRST などの情報からまとめて見られる（2026-11-20 追加）。Zero Wire のブリーフィングが引用した CVE は CVE ページへリンクし、CVE ページからもそのブリーフィングへ戻れる。

やることURL・操作
1 件を開く/zero-wire/cves/CVE-2021-44228（Log4Shell の例）。検索バー・Cmd / Ctrl + K に CVE ID や語を入れてもよい
一覧で探す/zero-wire/cves。日付・CVSS で並べ替え、CVE ID や製品名・ベンダー名で検索、深刻度・年で絞り込み。行には KEV 掲載と修正の有無が印で出る
新しい CVE を購読するRSS /zero-wire/cves/feed・Atom ?format=atom・JSON ?format=json
重大なものだけ購読するフィードに ?severity=critical を付ける（?format=json&severity=critical のように併用）
解説つきのまとめを追うZero Wire の RSS /security/zero-wire/rss（CVE フィードより件数が少なく、重大なものに絞られる）

CVE ページ用の API は公開されていない（2026-11 時点）。プログラムで扱うなら JSON フィードを使う。

ブロック載っているもの読み方
ヘッダーCVSS スコア・説明・公開日などの日付まず何の製品の何の脆弱性かを把握する
ExploitationCISA KEV の掲載（ランサムウェアでの利用も）・CISA SSVC・FIRST EPSS「実際に悪用されているか・されそうか」。優先度はここで決まる（次のタブ）
Affected productsベンダー・製品・バージョン（CVE を出した組織と NVD の両方）自分の使っている版が範囲に入るかを確かめる。両者が食い違うことがあるので、ベンダーの勧告で最終確認する
Recommended actions修正版、または当面のリスク低減策。KEV 掲載なら CISA の指示すぐ更新できないときの回避策もここで探す
Severityすべての CVSS スコアと各指標の説明攻撃元区分（ネットワーク越しか）・認証の要否・利用者の操作の要否を見ると、自分の環境での危なさが分かる
WeaknessesCWE（弱点の種類）と CAPEC（攻撃パターン）同じ種類の弱点がほかにないか探す手がかり
References勧告・パッチ・その他の出典一次情報（ベンダーの勧告）にたどる

CVSS は「起きたらどれだけ深刻か」で、「狙われているか」は表さない。Exploitation の 3 つで実際の危なさを足して判断する。

指標出しているところ意味
KEVCISA実際に悪用が確認された脆弱性の一覧。載っていれば「もう狙われている」
SSVCCISA悪用状況・技術的な影響・自動化できるか・組織での使われ方・公共への影響の 5 つから、対応の判断を Track・Track*・Attend・Act（右ほど急ぐ）で出す枠組み
EPSSFIRST今後 30 日以内に悪用される確率の推定（0〜1）
CVSSCVE を出した組織・NVD など脆弱性そのものの深刻度（0〜10）。出す組織によって値が違うことがある
  1. 使っているか確かめるAffected products に自分の製品・版が入っていなければ、ほかの指標が高くても対象外。
  2. KEV に載っているか載っていれば最優先。ランサムウェアでの利用ありなら、なおさら急ぐ。
  3. SSVC と EPSS を見るAct / Attend や EPSS が高いものを、KEV 未掲載の中で先にする。
  4. CVSS の指標で自分の環境に当てはめるネットワーク越しに認証なしで突けるか、外に公開しているか、で順番を調整する。
  5. Recommended actions で直す修正版に上げる。すぐ上げられなければ回避策と、WAF などでの防御（Zero Wire の Cloudflare coverage）を確かめる。

URL Scanner

URL をサンドボックスのブラウザで開き、スクリーンショット・通信の記録（HAR）・読み込んだ外部資源・使っている技術・悪性判定（verdicts.malicious）をレポートにする。Radar の /scan、ダッシュボードの Security Center、API のどれからでも使える。

  1. URL を入れるradar.cloudflare.com/scan に URL を貼る。社内の URL や個人情報を含む URL なら、公開範囲を Unlisted にする。
  2. レポートを読むSummary（判定・最終的な URL・IP・AS）、Security、Network（リクエスト一覧）、Behavior、Indicators のタブを見る。
  3. 保存・共有するSave as PDF で全タブを 1 つの PDF に、JSON でも保存できる。「Explain with AI」でレポートの読み方を AI に聞ける。
POST v2/scanURL を送る。uuid が返る
GET v2/result/{uuid}終わるまで 404。10〜30 秒おきに確かめる
200 で完了レポートの JSON。スクリーンショット・HAR は別のエンドポイント
# トークン: Account > URL Scanner を Edit で作る
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/urlscanner/v2/scan" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "visibility": "Unlisted",
    "screenshotsResolutions": ["desktop", "mobile"],
    "customagent": "my-scanner",
    "referer": "https://mail.example.com"
  }'
オプション意味
visibilityPublic（既定。最近のスキャン一覧と検索に載る）か Unlisted（ID を知る人だけが見られる）
screenshotsResolutionsdesktop・mobile・tablet から複数
customagent・refererUser-Agent と Referer を変える（スマホ向けや、メール経由のときだけ出るページを見る）
customHeaders任意のヘッダー（Authorization など）を付ける
v2/bulk最大 100 件をまとめて送る。優先度が低く、終わるのが遅くなることがある

Radar API

画面と同じデータを取り出せる無料の API。トークンは「Custom Token」で Account > Radar を Read にして作る。ベース URL は https://api.cloudflare.com/client/v4/radar/（アカウント ID は要らない）。

curl "https://api.cloudflare.com/client/v4/radar/http/summary/device_type?dateRange=7d&format=json" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
パラメータ意味
dateRange7d など。7dControl はその前の 7 日（比較用）
dateStart・dateEndUTC の日時（2026-11-01T00:00:00Z）。URL エンコードする
location・asn国（JP）や AS（13335）で絞る
aggInterval時系列の粒度 15m・1h・1d・1w
botClassLIKELY_AUTOMATED（ボット）・LIKELY_HUMAN（人）
formatjson か csv（pandas などにそのまま読ませる）
name系列に名前を付ける。返り値のキーになる（下の「比較する」）

返り値の meta に、実際に使われた期間・粒度・信頼度（confidenceInfo）が入る。7d のような指定は実行時に日付へ変わるので、何の期間だったかは meta で確かめる。

パス（/radar 以下）取れるもの
/attacks/layer7/timeseries・/summary/{dimension}L7 攻撃の推移・内訳（layer3 にすると DDoS）
/annotations/outagesOutage Center の障害（場所・原因・範囲・期間）
/traffic_anomalies障害の兆候かもしれない通信の異常
/bgp/hijacks/eventsBGP ハイジャックの検知。involvedAsn・minConfidence=8（高信頼のみ）
/bgp/leaks/events経路リークの検知（今はプロバイダ→顧客→プロバイダ型のみ）
/bgp/rpki/aspa/snapshotASPA の登録状況
/ct/timeseries・/ct/summary/{dimension}証明書発行の推移・CA ごとの内訳
/post_quantum/tls/support指定したホストのポスト量子 TLS 対応と、TLS 実装の不具合
/netflows/timeseriesルーターで見た通信量の推移（正規化した値）

ハイジャックの confidence_score は 1〜3 が低、4〜7 が中、8 以上が高。全エンドポイントは API リファレンスを参照。

name で系列を始め、続くパラメータがその系列に付く。並び順で系列が決まる。

# 日本とアメリカの直近 7 日を 1 回で
/radar/netflows/timeseries?name=jp&dateRange=7d&location=JP&name=us&dateRange=7d&location=US&format=json

# 今週と先週
/radar/netflows/timeseries?name=this_week&dateRange=7d&location=JP&name=last_week&dateRange=7dControl&location=JP

NetFlows のように最小・最大で正規化する値は、別々のリクエストで取った数字どうしを比べられない。比べたい系列は 1 回のリクエストにまとめる。

通知で見張る

ダッシュボードの Notifications で Radar の通知を作ると、指定した国・地域・ASN に変化があったときに知らせてくれる。種類は anomaly（通信の異常）・outage（障害）・route hijack（経路の乗っ取り）・route leak（経路リーク）の 4 つ。送り先はメール・Webhook・PagerDuty。

細かく制御したいときは、Workers で API を定期的に叩く方法が公式ドキュメントに載っている。

よくある誤解

Radar を見れば自分のサイトへの攻撃状況が分かる

Radar はインターネット全体を集計した傾向で、特定のサイトの数字は出ない。自分のゾーンの攻撃は、ダッシュボードの Security Analytics などで見る。

グラフの値は通信量や攻撃の件数そのものだ

多くのグラフは割合や、最小〜最大で 0〜1 に正規化した値で、絶対量は出していない。しかも Cloudflare から見えた範囲だけなので、比較は同じ条件の中で行う。

CVSS が高い順に直せば、危ない順に直したことになる

CVSS は脆弱性そのものの深刻度で、実際に狙われているかは表さない。CVSS が中程度でも KEV に載っているものの方が急ぐべきことが多い。CVE ページの Exploitation（KEV・SSVC・EPSS）を合わせて見る。

URL Scanner に入れた URL は自分にしか見えない

既定は Public で、最近のスキャン一覧と検索に載る。トークン入りの URL や社内の URL は、Unlisted にしてから調べる（Free では Unlisted が使えないので、そもそも入れない）。

URL Scanner で malicious と出なければ安全だ

判定はスキャンした時点・その条件での結果にすぎない。相手が UA や地域で中身を切り替えることもあるので、リダイレクト先・読み込んだ資源・似た構造のページも合わせて見る。

API のデータは出典を書けば仕事の資料に自由に使える

API のデータは CC BY-NC 4.0 で、営利目的には使えない。グラフの埋め込みや画像は CC BY 4.0 なので、社外向けにはそちらを使うか、Cloudflare に相談する。
