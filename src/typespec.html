TypeSpec 使い方

API を型で書いて OpenAPI・JSON Schema・コードを生成する Microsoft 製の言語（v1.18 時点）

ざっくり言うと
  • TypeScript 風の構文で API の形を書く言語で、拡張子は .tsp、CLI は tsp。
  • tsp compile が型を読み、tspconfig.yaml で選んだ emitter が OpenAPI などを書き出す。
  • 安定版は compiler・http・openapi3・json-schema など一部。クライアント／サーバー生成はまだプレビュー。

全体の流れ

main.tspmodel・op・デコレーター
tsp compile型チェック・linter
@typespec/openapi3openapi.yaml
@typespec/json-schema*.yaml（JSON Schema）
@typespec/protobuf*.proto
http-client-* / http-server-*クライアント・サーバーのコード

どの emitter を動かすかは tspconfig.yaml の emit か --emit で決める。何も指定しないと型チェックだけで、何も出力されない。

セットアップ

  1. CLI を入れるnpm install -g @typespec/compiler（Node.js LTS が前提）。Node なしなら curl -fsSL https://typespec.io/install.sh | bash の単体版（実験的）。
  2. プロジェクトを作るtsp init でテンプレートを選ぶ。REST なら「Generic REST API」（http・rest・openapi・openapi3 が入る）。
  3. 依存を入れるtsp install（package.json の依存を入れる。npm install でもよい）。
  4. コンパイルtsp compile .。保存のたびに作り直すなら tsp compile . --watch。
  5. エディターVS Code は Marketplace の「TypeSpec」拡張を入れる（tsp code install は非推奨）。
できるファイル中身
main.tsp入口。tsp compile . はこのファイルから読む
tspconfig.yamlemitter とそのオプション、linter
package.jsoncompiler・ライブラリ・emitter の版
tsp-output/出力先（既定は {cwd}/tsp-output）。OpenAPI は tsp-output/@typespec/openapi3/openapi.yaml

コマンド用途

--trace <area> / --debug内部ログ（例: import-resolution.*）
--statsコンパイルの統計を表示
コマンド用途
npx tsp-openapi3 openapi.yaml --output-dir ./tsp既存の OpenAPI 3 を TypeSpec に変換（@typespec/openapi3 に同梱）。--namespace で名前空間を指定
TYPESPEC_NPM_REGISTRY環境変数。tsp init・tsp install が使う npm レジストリ（社内ミラー用）

tspconfig.yaml

emit:
  - "@typespec/openapi3"
  - "@typespec/json-schema"

output-dir: "{project-root}/generated"   # 既定は {cwd}/tsp-output

options:
  "@typespec/openapi3":
    openapi-versions: ["3.1.0"]           # 既定は ["3.0.0"]。"3.2.0" も可
    file-type: yaml                       # yaml | json（配列で両方）
    emitter-output-dir: "{output-dir}/openapi"
    output-file: "openapi.{version}.yaml"

linter:
  extends:
    - "@typespec/http/all"
キー意味
emit動かす emitter（CLI の --emit）
optionsemitter ごとのオプション（CLI の --option）
output-dir全体の出力先。各 emitter は既定で {output-dir}/<emitter名> に出す
emitter-output-diremitter 共通のオプション。その emitter だけ出力先を変える
extends別の tspconfig.yaml を継承。同じ emitter の設定は丸ごと上書き（キー単位でマージしない）
parameters自前の変数。既定値が必須で、--arg で上書き
environment-variables使う環境変数の宣言（既定値が必須）。{env.NAME} で参照
linterextends・enable・disable。v1.16 から "file:../rules.yaml" で共有ファイルも参照できる

変数は {project-root}（設定ファイルのあるフォルダ）・{cwd}・{output-dir}・{emitter-name} など。環境変数は environment-variables: に既定値つきで宣言すると {env.NAME} で使える。設定ファイルは入口の .tsp と同じフォルダから親へ向かって探し、最初に見つかったものを使う。CLI の指定は設定ファイルより優先される。

言語の基本

型中身・OpenAPI での形
string / boolean / bytes文字列・真偽値・バイナリ（JSON では base64）
int8〜int64, uint8〜uint64整数（format: int32 など）
integer / safeint任意長の整数 ／ JS で安全な範囲の整数
float32 / float64 / decimal / numeric小数。numeric は数値全体の親
utcDateTime / offsetDateTime日時（format: date-time）
plainDate / plainTime / duration日付・時刻・期間
urlformat: uri
T[] / Record<T>配列 ／ 値が T の辞書（additionalProperties）
[string, int32]タプル
unknown / void / never / null何でも ／ 本文なし ／ ありえない ／ null
 
/** ペット（doc コメントは description になる） */
model Pet {
  id: string;
  name: string;
  age?: int32;              // ? で任意
  tags: string[] = #[];     // 既定値（配列は #[ ]、オブジェクトは #{ }）
  owner: Owner | null;      // null 許容
  kind: "dog" | "cat";      // リテラル型の union
}

scalar petId extends string;                  // 独自のスカラー
@format("email") scalar email extends string; // 形式付き

再利用の書き方（extends / is / ...）は下の「model の再利用」を参照。

enum Kind { dog, cat, bird }             // 値は名前と同じ文字列
enum Level { low: 1, high: 10 }          // 値を指定

union Status { "active", "disabled", string }  // 拡張可能な列挙（anyOf）

@discriminated(#{ envelope: "none", discriminatorPropertyName: "kind" })
union Shape { circle: Circle, square: Square } // oneOf + discriminator
model Circle { kind: "circle"; r: float64 }
model Square { kind: "square"; size: float64 }

enum は閉じた列挙。あとから値が増えるなら、最後に string を足した union にしておく。

model Page<T> {
  items: T[];
  nextLink?: url;
}
model Paged<T extends {}> { value: T[] }   // 制約付き
model Box<T = string> { v: T }            // 既定の型

alias PetPage = Page<Pet>;                // 別名（出力に新しい型は出ない）

op list(): Page<Pet>;
デコレーター対象OpenAPI での形
@doc("…") / /** … */なんでもdescription
@summary("…")op などsummary
@minLength(n) / @maxLength(n)文字列minLength / maxLength
@minValue(n) / @maxValue(n)数値minimum / maximum
@minItems(n) / @maxItems(n)配列minItems / maxItems
@pattern("^…$")文字列pattern
@format("email")文字列format
@secret文字列format: password
@encode(…)日時・bytes など直列化の形（例: DateTimeKnownEncoding.rfc3339）
@visibility(Lifecycle.Read)プロパティ読み取り専用（readOnly）。Create・Update・Query もある
@example(…) / @opExample(…)型 ／ opexamples
#deprecated "理由"なんでも非推奨（ディレクティブ）
 
import "@typespec/http";     // ライブラリ（package.json に入れておく）
import "./models/pet.tsp";   // 自分のファイル

using Http;                  // 名前空間を開く（書かないと Http.Body のように完全名）

namespace PetStore;          // ファイル全体をこの名前空間に
namespace PetStore.Admin { } // ブロックでも書ける

interface Pets { list(): Pet[]; }   // op のまとまり

model の再利用

書き方意味OpenAPI での形
model Staff extends User { … }継承。親子関係が残るallOf: [$ref User] ＋ 追加分
model Admin is User { … }コピー（デコレーターも引き継ぐ）。関係は残らない全プロパティを持つ別スキーマ
model A { ...Timestamps; … }プロパティだけ展開（spread）A に平らに入る
alias PetPage = Page<Pet>;別名。新しい型は作らない出ない
OmitProperties<T, "id"> / PickProperties / OptionalProperties組み込みの型変換テンプレート変換後の新スキーマ

HTTP（@typespec/http）

デコレーター付ける所用途
@service(#{ title: "…" })namespaceサービスの入口。無いと paths が空の OpenAPI になる（no-service-found の警告）
@server("https://…", "説明")namespaceservers
@route("/pets")namespace・interface・opパス。親の route に連結される
@get @post @put @patch @delete @headopHTTP メソッド。省略時は本文があれば POST、無ければ GET
@path引数パス引数。@route に無ければ /{id} が自動で付く
@query / @query("q")引数クエリ。@query(#{ explode: true }) で配列の展開
@header / @header("x-req-id")引数・レスポンスヘッダー。名前を省くと contentType → content-type に変換
@body引数・レスポンス本文そのもの（型がそのまま本文）
@bodyRoot引数・レスポンス本文の根。中の @header などは本文から外れる
（何も付けない引数）引数本文のプロパティとしてまとめられる
@statusCodeレスポンスのプロパティステータスコード（201 や 400 | 404）
@errormodelエラー型。@statusCode が無ければ default レスポンスになる
@tag("Pets")namespace・interface・opOpenAPI の tags（@typespec/openapi）
@operationId("…")opoperationId の指定（@typespec/openapi）
 
// 型を返すだけなら 200 + JSON
@get op read(@path id: string): Pet | NotFoundResponse;

// ステータスやヘッダーを付ける
@post op create(@body pet: Pet): {
  @statusCode _: 201;
  @header location: string;
  @body pet: Pet;
} | ApiError;

// 組み込みのレスポンス型と合成（read と同じパスなので別の route で）
@get @route("/v2") op get2(@path id: string): OkResponse & { @body body: Pet };

@delete op remove(@path id: string): NoContentResponse;   // 204

@error model ApiError {
  @statusCode _: 400 | 500;
  code: string;
  message: string;
}

組み込み: OkResponse（200）・CreatedResponse（201）・AcceptedResponse（202）・NoContentResponse（204）・MovedResponse（301）・NotModifiedResponse（304）・BadRequestResponse（400）・UnauthorizedResponse（401）・ForbiddenResponse（403）・NotFoundResponse（404）・ConflictResponse（409）。

@useAuth(BearerAuth)                                    // Authorization: Bearer
@useAuth(BasicAuth)
@useAuth(ApiKeyAuth<ApiKeyLocation.header, "X-API-KEY">)
@useAuth(ApiKeyAuth<ApiKeyLocation.header, "X-API-KEY"> | BearerAuth)  // どちらか
@useAuth([ApiKeyAuth<ApiKeyLocation.header, "X-API-KEY">, BearerAuth]) // 両方
@useAuth(NoAuth | BearerAuth)                           // 認証なしも可
@useAuth(OAuth2Auth<[MyFlow]>)                          // OAuth2（フローは model で定義）

namespace に付けると全体、op や interface に付けるとそこだけ上書き。

まとまった例

import "@typespec/http";
import "@typespec/openapi";
using Http;

@service(#{ title: "Pet Store" })
@server("https://api.example.com", "本番")
@useAuth(BearerAuth)
namespace PetStore;

model Pet {
  @visibility(Lifecycle.Read) id: string;
  @minLength(1) @maxLength(50) name: string;
  @minValue(0) age?: int32;
  tags: string[] = #[];
}

@error model ApiError {
  @statusCode _: 400 | 404 | 500;
  code: string;
  message: string;
}

model Page<T> { items: T[]; nextLink?: url; }

@route("/pets")
@tag("Pets")
interface Pets {
  @get list(@query limit?: int32 = 20, @query("q") search?: string): Page<Pet> | ApiError;
  @get read(@path id: string): Pet | NotFoundResponse;
  @post create(@body pet: Pet): { @statusCode _: 201; @body pet: Pet } | ApiError;
  @patch update(@path id: string, @body pet: MergePatchUpdate<Pet>): Pet;
  @delete delete(@path id: string): NoContentResponse;
}
paths:
  /pets:
    get:
      operationId: Pets_list
      parameters:
        - name: limit
          in: query
          ...
    post:
      operationId: Pets_create
      responses:
        '201': ...
        '400': ...   # ApiError の 400 | 404 | 500 がそれぞれ出る
  /pets/{id}:          # @path id が自動でパスに付く
    get:    { operationId: Pets_read }
    patch:
      operationId: Pets_update
      requestBody:
        content:
          application/merge-patch+json: ...
    delete: { operationId: Pets_delete }
security:
  - BearerAuth: []

バージョニング（@typespec/versioning）

import "@typespec/versioning";
using Versioning;

@versioned(Versions)
@service
namespace PetStore;
enum Versions { v1, v2, v3 }

model Pet {
  name: string;
  @added(Versions.v2) nickname?: string;                  // v2 から
  @removed(Versions.v3) legacy?: string;                  // v3 で削除
  @renamedFrom(Versions.v2, "fullName") displayName: string;
  @typeChangedFrom(Versions.v2, int32) weight: float64;
}

@added(Versions.v2) op search(): Pet[];

openapi3 emitter は版ごとに 1 ファイル出す（openapi.v1.yaml・openapi.v2.yaml…）。ほかに @madeOptional・@madeRequired・@useDependency（依存ライブラリの版を固定）がある。

TypeScript のクライアントや型は、openapi3 で OpenAPI を出してから既存の OpenAPI 用ジェネレーターに渡す使い方も多い。

ハマりどころ

  1. 何も出力されないemit も --emit も無いと型チェックだけで終わる。namespace に @service が無いと paths が空の OpenAPI になる。
  2. 出力先がずれる既定の output-dir は {cwd}/tsp-output。別のフォルダから tsp compile path/to/proj すると、実行した場所に出る。固定したいなら output-dir: "{project-root}/tsp-output"。
  3. デコレーターが見つからないimport "@typespec/http"; に加えて using Http; が要る（無ければ @Http.route と書く）。
  4. PATCH の本文が全部必須になる@patch(#{ implicitOptionality: true }) は非推奨の警告が出る。merge-patch なら @body pet: MergePatchUpdate<Pet>、そうでなければ任意プロパティの model を自分で書く。
  5. OpenAPI が 3.0 で出るopenapi-versions の既定は ["3.0.0"]。3.1 が欲しければ明示する。
  6. 使っていない型まで出る既定ではサービスの namespace 内の型を全部出す。omit-unreachable-types: true で op から参照されるものだけにする。
  7. enum に値を足すと互換が崩れるクライアントが閉じた列挙として生成するため。増える見込みがあれば union X { "a", "b", string } にする。

よくある誤解

TypeSpec は Azure 専用の言語だ

汎用の API 記述言語で、@typespec/* のライブラリだけで普通の REST API の OpenAPI を出せる。Azure 向けの規約は @azure-tools/typespec-* という別のライブラリに分かれている。

TypeSpec で書いた制約は実行時に検証される

TypeSpec は設計時のツールで、出力は OpenAPI などの定義ファイル。リクエストの検証は、生成した定義やコードを使うサーバー側で別に行う。

extends と is は同じ意味だ

extends は親子関係が残り OpenAPI では allOf になる。is は中身をコピーした別の型で、関係は出力に残らない。
