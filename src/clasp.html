clasp 使い方

Google Apps Script（GAS）をローカルのコードとして管理する CLI（3.x）

ざっくり言うと
  • GAS のプロジェクトをローカルに持ってきて、Git やエディタで管理できるようにする、Google が公開しているオープンソースの CLI。
  • clone・pull で取得し、push で上書き、deploy で版を固定して公開する。
  • 3.x は TypeScript を変換しない。push はリモートを丸ごと置き換えるので .claspignore を必ず確かめる。

ローカルとリモートの関係

ローカルGit で管理するフォルダ.clasp.json / appsscript.json / *.js *.gs *.html
push pull clone
script.google.comApps Script プロジェクト（HEAD）scriptId で特定。フォルダは「tests/slides」のような名前になる
create-versionHEAD の内容から、変更できない版（version）を作る
create-deployment版を作ってデプロイ（ウェブアプリは デプロイごとに URL）
update-deployment同じデプロイ ID のまま新しい版に差し替える

ローカルの tests/slides.js は、リモートでは tests/slides.gs というフラットな名前になる（clasp が相互に変換する）。

はじめかた

  1. インストールnpm install -g @google/clasp（Node.js 20 以上。clasp -v で版を確認）
  2. Apps Script API を有効にするscript.google.com/home/usersettings で「Google Apps Script API」をオンにする。オフのままだと API を呼ぶコマンドが失敗する
  3. ログインclasp login。ブラウザで認可すると、ホームの ~/.clasprc.json に認証情報が保存される。ブラウザが開けない環境は --no-localhost
  4. プロジェクトを作るか持ってくる新規は clasp create-script --title "名前" --type sheets、既存は clasp clone-script <scriptId または URL>。どちらも .clasp.json ができる
  5. 書いて送る編集したら clasp show-file-status で送るファイルを確かめ、clasp push。clasp open-script でエディタを開いて動作を見る

コマンド チートシート

左の列は 3.x の正式名。別名 は主に 2.x の名前で、今も使える。注意 は、リモートやローカルのファイルを消す・上書きする操作。

コマンドやること
clasp loginブラウザで認可して ~/.clasprc.json に保存（ユーザー名は default）
clasp login --no-localhostローカルのサーバーを立てず、表示されたコードを手で貼る（SSH 先など）
clasp login --redirect-port 37473認可の戻り先のポートを指定する
clasp login -u work --creds client_secret.json自前の OAuth クライアント（デスクトップ アプリ）で、名前付きの認証情報を作る
clasp login --use-project-scopes --creds …appsscript.json の oauthScopes で認可する（run-function 用）。--include-clasp-scopes で clasp の既定スコープも足す
clasp login --extra-scopes a,b追加のスコープをカンマ区切りで足す
clasp show-authorized-userログイン中のユーザーと、OAuth クライアントが既定（google-provided）か自前（user-provided）かを表示。--json も可
clasp logout保存した認証情報を消す
clasp 任意 --user workどのコマンドでも、名前付きの認証情報で動かす（アカウントの切り替え）
コマンドやること
clasp create-script create新しいプロジェクトを作る。--type を省くと standalone になる
create-script --type sheets新しいスプレッドシートに紐づいた（コンテナバインドの）スクリプトを作る。docs・slides・forms・standalone（既定）。webapp・api は standalone の別名
create-script --parentId <DriveのID>既存のドキュメント・シートなどに紐づけて作る。--type は省くか standalone にする（docs・sheets などを付けると新しいファイルが作られ、--parentId は使われない）
create-script --title "名前" --rootDir ./srcタイトルと、ファイルを置くローカルのフォルダを指定
clasp clone-script <scriptId|URL> clone既存のプロジェクトを取得して .clasp.json を作る。--rootDir・版番号も指定できる
clasp list-scripts list自分の最近のプロジェクトを名前と ID で一覧
clasp delete-script delete 注意プロジェクトを Drive のゴミ箱に移す（ローカルの .clasp.json は残る）。-f で確認を飛ばす
コマンドやること
clasp show-file-status statuspush で送られるファイルの一覧（無視されるファイルも分かる）。--json も可
clasp push 注意ローカルのファイルでリモートを丸ごと置き換える（ファイル単位の差分ではない）
clasp push -fマニフェスト（appsscript.json）の上書き確認を飛ばす
clasp push -wファイルの変更を監視して、無視対象でないファイルが変わるたびに push
clasp pullリモートの内容でローカルを更新する
clasp pull --versionNumber 23指定した版の内容を取得する
clasp pull -d 注意リモートに無いローカルのファイルを消す（確認あり。-f で確認なし）
コマンドやること
clasp create-version "説明" version今の HEAD から変更できない版を作る
clasp list-versions versions版の一覧
clasp create-deployment deploy新しい版を作って新しいデプロイを作る。-d "説明"、既存の版を使うなら -V 4
clasp update-deployment <id> redeployデプロイ ID（＝ウェブアプリの URL）を変えずに新しい版へ差し替える。create-deployment -i <id> と同じ
clasp list-deployments deploymentsデプロイの一覧（ID と版）
clasp delete-deployment <id> undeploy 注意デプロイを消す。ID を省くと選択（1 つだけならそれを消す）、--all で全部
コマンドやること
clasp open-scriptこのプロジェクトの Apps Script エディタを開く
clasp open-web-appデプロイしたウェブアプリを開く
clasp open-container紐づいているドキュメント・シートなどを開く
clasp open-credentials-setupOAuth クライアントを作る Cloud Console の画面を開く
clasp open-logsCloud Logging の画面を開く
clasp open-api-consoleAPI の有効化を管理する Cloud Console を開く
コマンドやること
clasp setup-logsログを読むのに要る GCP プロジェクト ID を設定する
clasp tail-logs logsCloud Logging の新しいログを表示。--watch で追い続ける、--simplified で時刻を省く、--json
clasp run-function myFunc run関数をリモートで実行して結果を表示。省くと候補から選ぶ。準備は下の「run-function の準備」
run-function f -p '["a",1]'引数を JSON の配列で渡す。--nondev で最新コードではなくデプロイ版で動かす

clasp start-mcp-server mcpコーディングエージェント用の MCP サーバーとして起動する（実験的、STDIO）

該当するコマンドはありません。

どのコマンドにも付けられるオプション

オプションやること
-u, --user <name>名前付きの認証情報を使う（既定は default）
-P, --project <file>.clasp.json 以外の設定を読む（本番・検証など送り先を分ける）。環境変数 clasp_config_project
-I, --ignore <file>.claspignore 以外の無視リストを読む。環境変数 clasp_config_ignore
--json出力を JSON にする
--allow-symlinksシンボリックリンクのファイル・フォルダも push・pull の対象にする（3.4 から）
--adc環境のアプリケーションのデフォルト認証情報を使う（サービスアカウント向け。README では実験的・未完成の扱い）

不具合を調べるときは DEBUG=clasp:* clasp pull で詳しいログが出る。プロキシは HTTP_PROXY・HTTPS_PROXY で通す。

2.x からの変更（3.x）

よく使うコマンドは別名でそのまま動く。名前が変わって別名が無いのは次のもの。

2.x3.x
openopen-script
open --web / --addon / --credsopen-web-app / open-container / open-credentials-setup
login --creds <file>login -u <name> --creds <file>
logs --openopen-logs
apis --open / apis enable x / apis disable xopen-api-console / enable-api x / disable-api x
deploy -i <id>update-deployment <id>
logs --setup・settingsなし

もう 1 つの大きな変更は TypeScript の変換をやめたこと。.ts は Rollup などのバンドラーで JS にしてから push する（下の「TypeScript で書く」）。

.clasp.json

create-script・clone-script がカレントフォルダに作る。リポジトリにコミットしてよい（認証情報は入らない）。

{
  "scriptId": "1D_Gxyv…NXO7o",
  "rootDir": "dist",
  "projectId": "my-gcp-project",
  "scriptExtensions": [".js", ".gs"],
  "htmlExtensions": [".html"],
  "filePushOrder": ["dist/polyfill.js"]
}
キー意味
scriptId必須。対象のプロジェクト ID（エディタの「プロジェクトの設定」にある）
rootDirローカルのファイルを置くフォルダ。省くとカレントフォルダ
projectId紐づける GCP プロジェクト ID。ログ・run-function・API の有効化で使う。無ければ必要なときに聞かれる
scriptExtensionsスクリプトとして扱う拡張子（既定 [".js", ".gs"]）。pull で書き出すときは先頭の拡張子になる
htmlExtensionsHTML として扱う拡張子（既定 [".html"]）
filePushOrder先に送るファイル。読み込み順に依存するコード向け。パスは .clasp.json のあるフォルダからで、rootDir も含めて書く
skipSubdirectoriestrue で .claspignore が無いときにサブフォルダを無視する（昔の動きに合わせる）
fileExtension非推奨。scriptExtensions を使う

.claspignore

push から外すファイルのパターン。rootDir からの相対で、.gitignore ではなく multimatch の書き方になる。フォルダを外すときは **/node_modules/** のように書く。. で始まるファイルと、対象外の拡張子はもともと送られない。

# ビルド結果とマニフェストだけを送る
**/**
!appsscript.json
!main.js

ファイルが無いときの既定は「appsscript.json と *.gs・*.js・*.ts・*.html だけを対象にし、.git/・node_modules/ は除く」。ただし *.ts は拡張子（scriptExtensions）の判定で外れるので、実際には送られない。

TypeScript で書く

3.x は変換しないので、バンドラーで 1 本の JS にしてから push する。どれを選んでも共通の準備は次のとおり。

  1. 型を入れるnpm i -D @types/google-apps-script で SpreadsheetApp などに型が付く
  2. dist だけを送る.clasp.json の rootDir を dist にし、appsscript.json も dist/ に置く
  3. ビルドと push をまとめる"push": "node build.mjs && clasp push" のように 1 つのスクリプトにする

定番の組み合わせ。バンドルすると関数は外から見えなくなるので、GAS から呼ぶ関数（トリガー・doGet・カスタム関数など）は入口のファイルで global に代入する。esbuild-gas-plugin がその代入を読み、トップレベルの関数を出力の先頭に足す。

npm i -D esbuild esbuild-gas-plugin \
  typescript @types/google-apps-script
// build.mjs
import { build } from "esbuild";
import { GasPlugin } from "esbuild-gas-plugin";

await build({
  entryPoints: ["src/main.ts"],  // 配列で書く（使われるのは先頭の 1 つだけ）
  bundle: true,
  outfile: "dist/main.js",       // 必須（write: false は使えない）
  plugins: [GasPlugin],
});
// src/main.ts（入口）
import { sum } from "./lib";

const onOpen = () => { /* … */ };
/** @customfunction */
const SUM2 = (a: number, b: number) => sum(a, b);

global.onOpen = onOpen;   // ここに書いた関数だけが GAS から呼べる
global.SUM2 = SUM2;

global の代入は入口のファイルにだけ書く（ほかのファイルの代入は拾われない）。global に型が無いと言われたら declare const global: any; などで宣言する。esbuild-gas-plugin は 0.x（0.10.0）。

まだ 0.x で枯れていないが、有用な選択肢。GAS 向けの TypeScript プロジェクトを対話で生成する CLI で、バンドル（Rolldown）・Biome・Vitest・.clasp.json の設定まで一度に用意する。React・Vue で GAS のウェブアプリを作るテンプレートもある。

# 対話で作る
npx @ciderjs/gasbombe

# 対話なし（全部指定する。省いた項目だけ聞かれる）
npx @ciderjs/gasbombe -n my-app -t server-ts \
  -c create -p pnpm -g
オプション意味
-n, --nameプロジェクト名（. でカレントフォルダに展開）
-t, --templateserver-ts・server-js・react・vue・html-js と、CiderJS 版の server-ciderjs・react-ciderjs・vue-ciderjs（全 8 種）
-c, --clasp.clasp.json の作り方。create（新規）・list（一覧から選ぶ）・input（ID を入力）・skip。create・list は先に clasp login が要る
-p, --pkgnpm・pnpm・yarn。--skipInstall で入れない
-g, --git / --skipGitGit の初期化をする・しない

生成物には AI コーディングエージェント向けのルール（.agents/・CLAUDE.md など）も入る。*-ciderjs テンプレートはサーバー関数の型をクライアントに渡す仕組みなど、同じ作者のライブラリ群を使う。確認時点は @ciderjs/gasbombe 0.5.3。

ほかの雛形は clasp の README に載っている（google/aside など。こちらは Rollup）。

run-function の準備

ローカルから関数を動かすには、自前の GCP プロジェクトと OAuth クライアントが要る（既定の clasp のクライアントでは動かない）。

  1. GCP プロジェクトを紐づけるエディタの「プロジェクトの設定」で GCP プロジェクト番号を設定し、.clasp.json に projectId を書く
  2. OAuth クライアントを作るclasp open-credentials-setup から種類「デスクトップ アプリ」で作り、JSON を client_secret.json として保存（コミットしない）
  3. 実行 API を許可するappsscript.json に "executionApi": { "access": "ANYONE" } を書き、スクリプトが使うスコープも oauthScopes に並べて push
  4. そのスコープでログインclasp login -u dev --use-project-scopes --creds client_secret.json
  5. 実行clasp run-function -u dev myFunc。「API executable として公開されていない」と出たら、エディタの「デプロイ」から種類「API 実行可能ファイル」でデプロイする

よくある誤解

push は変更したファイルだけを送るので、手元に無いファイルはリモートに残る

Apps Script API にはファイル単位の更新が無く、push は毎回プロジェクトの中身を丸ごと置き換える。ローカルに無いファイルはリモートから消える。エディタで直接足したファイルがあるなら、先に pull する。

clasp 3.x でも .ts をそのまま push すれば JS に変換される

変換は 2.x まで。3.x では .ts は対応していない拡張子として push の対象から外れる（送られない）。バンドラーで JS にしてから送る。

clasp logs で Logger.log の出力が見られる

tail-logs（logs）が読むのは Cloud Logging のログで、console.log の出力で、Logger.log は対象外（README）。Logger.log はエディタの実行ログで見る。GCP プロジェクトの紐づけ（setup-logs）も要る。

.claspignore は .gitignore と同じ書き方で効く

パターンは multimatch で解釈されるため、node_modules/ だけではフォルダの中身が外れないことがある。**/node_modules/** のように書き、show-file-status で結果を確かめる。

create-deployment し直してもウェブアプリの URL は同じ

create-deployment は毎回新しいデプロイ（新しい URL）を作る。同じ URL のまま更新するなら update-deployment <id>。
