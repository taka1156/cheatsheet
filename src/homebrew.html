Homebrew 使い方

macOS・Linux のパッケージマネージャー brew のチートシート（Homebrew 7.0 系、7.0.15 時点）

ざっくり言うと
  • Homebrew は CLI ツール（formula）と Mac アプリ（cask）を brew コマンド 1 つで入れて更新するパッケージマネージャー。
  • ビルド済みの bottle を Cellar に展開し、prefix の bin などへシンボリックリンクを張るので sudo は要らない。
  • 6.0 から公式以外の tap は brew trust で信頼するまで読み込まれず、7.0 で brew vulns が加わった。

仕組みと用語

パッケージ定義（Ruby のファイル）は tap というリポジトリにまとまっている。公式の homebrew/core（formula）と homebrew/cask（cask）は、普段は Git で取り込まずに JSON の API から読む。

tapformula・cask・外部コマンドの定義を置くリポジトリhomebrew/core, homebrew/cask, user/repo
bottleビルド済みのバイナリ。無い環境ではソースからビルドする
Cellarバージョンごとのフォルダ（keg）に展開する$(brew --prefix)/Cellar/wget/1.25.0
prefixkeg の中身をリンクして PATH から使えるようにする$(brew --prefix)/bin/wget
formulaソースからビルドするパッケージの定義。CLI ツールやライブラリ（例: wget）。
caskビルド済みの macOS アプリなどを入れる定義（例: firefox）。Caskroom に置かれる。
keg1 つの formula の 1 バージョンを入れたフォルダ。opt/ には今のバージョンへのリンクがある。

はじめかた

  1. インストール下の公式スクリプトを実行する（Apple Silicon の Mac なら .pkg のインストーラーもある）。
  2. PATH を通すインストーラーが最後に表示する行（下の 2 行目のような形）を ~/.zprofile（Linux なら ~/.bashrc など）に足す。
  3. 確かめるbrew doctor で問題がないかを見る。警告が出ても困っていなければ無視してよい、と公式に書かれている。
  4. 入れるbrew install wget（CLI）、brew install --cask firefox（アプリ）。名前が formula と重ならなければ --cask は省ける。
# 1. インストール
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
# 2. PATH を通す（Apple Silicon の Mac の例）
eval "$(/opt/homebrew/bin/brew shellenv zsh)"

コマンドやること

brew unpin node固定を外す
brew list --pinned固定しているパッケージの一覧
brew update-reset 危険Homebrew と tap の Git リポジトリを origin/HEAD に戻す。手元の変更は消える

brew cleanup -n何が消えるかを表示するだけ

brew vulns --fix-available修正版が出ているものだけを表示

Brewfile（brew bundle）

入れるものを Brewfile に並べ、brew bundle でまとめて入れる。新しい Mac の準備や、チームで同じ道具をそろえるときに使う。formula・cask・tap のほか、Mac App Store（mas）、VS Code 拡張、Go・Cargo・npm・uv のツールなども書ける。

# Brewfile
# 公式以外の tap は trusted: true で信頼を宣言できる
tap "user/repo", trusted: true
brew "jq"
brew "postgresql@17", restart_service: true
cask "firefox"
mas "Xcode", id: 497799835
vscode "editorconfig.editorconfig"
# Ruby なので条件も書ける
brew "glibc" if OS.linux?
コマンドやること
brew bundle今のフォルダの Brewfile にあるものを入れる（brew bundle install と同じ。入っていて古ければ更新する）
brew bundle dump今入っているものを Brewfile に書き出す。既にあるファイルを上書きするなら --force
brew bundle checkBrewfile のものが全部入っているかを確かめる（足りなければ終了コードが 0 以外）
brew bundle cleanupBrewfile に無いものを消す。既定は消す前に確認し、--force で確認なしに消す
brew bundle listBrewfile の中身を一覧（既定は formula だけ）
brew bundle add jqBrewfile に項目を足す（--cask などで種類を指定）
brew bundle --file=path/Brewfile別の場所の Brewfile を使う
brew bundle --global~/.Brewfile など、ユーザー共通の Brewfile を使う

よく使う環境変数

変数効果
HOMEBREW_NO_AUTO_UPDATE=1install・upgrade・tap の前の自動 brew update をしない
HOMEBREW_AUTO_UPDATE_SECS自動 update の間隔（秒）。既定は 86400（24 時間）。止めるより間隔を延ばすのが推奨
HOMEBREW_NO_INSTALL_CLEANUP=1install・upgrade のあとの自動 cleanup をしない
HOMEBREW_NO_ASK=1インストール前の確認（ask モード）をしない
HOMEBREW_UPGRADE_GREEDY=1brew upgrade を常に --greedy で動かす
HOMEBREW_NO_ANALYTICS=1利用統計を送らない（brew analytics off でも止められる）
HOMEBREW_NO_ENV_HINTS=1環境変数についてのヒントを表示しない

よくある誤解

権限エラーが出たら sudo brew で実行すればよい

brew は prefix の持ち主のユーザーで動かす前提で、sudo を付けると prefix の持ち主が書き換えたコードを root で動かすことになる。権限エラーは prefix の持ち主を直す。例外は、起動時に root で動かしたいサービス（sudo brew services）など、ドキュメントが sudo を示している場合だけ。

brew update で入っているパッケージも新しくなる

brew update は Homebrew 本体とパッケージ定義を更新するだけ。パッケージを新しくするのは brew upgrade（brew outdated で対象を確認できる）。

brew upgrade ですべての cask が更新される

自分で更新するアプリ（auto_updates true）と version :latest の cask は既定で飛ばされる。まとめて上げるなら brew upgrade --greedy。

brew uninstall で依存パッケージも一緒に消える

消えるのは指定したものだけ。使われなくなった依存は brew autoremove で消す（-n で事前に確認できる）。

brew tap した tap の formula はそのまま入れられる

6.0 からは公式以外の tap は信頼が要る。brew install user/repo/foo と完全な名前で入れるか、brew trust で信頼してから短い名前で入れる。
