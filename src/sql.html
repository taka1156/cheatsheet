SQL チートシート

標準 SQL を軸に、PostgreSQL・MySQL・SQLite で書き方が違うところを並べた早見表

ざっくり言うと
  • SQL はテーブルに対して「何がほしいか」を書く言語で、SELECT・JOIN・集計・更新の基本はどの DB でもほぼ同じ。
  • 書く順と評価される順が違うので、SELECT の別名は WHERE で使えず、集計の絞り込みは HAVING に書く。
  • UPSERT・RETURNING・連番・文字列連結などは DB ごとに書き方が違うので、下の方言表で確かめる。

書く順と評価される順

/* 5 */ SELECT   列・式 AS 別名
/* 1 */ FROM     テーブル JOIN ...
/* 2 */ WHERE    行の条件
/* 3 */ GROUP BY まとめる列
/* 4 */ HAVING   グループの条件
/* 6 */ ORDER BY 並べ替え
/* 7 */ LIMIT    件数 OFFSET 開始位置;   -- /* n */ は評価される順番
FROM / JOIN元になる行の集まりを作る
WHERE行を絞る（集計関数は使えない）
GROUP BY行をグループにまとめる
HAVINGグループを絞る
SELECT列・式・別名・ウィンドウ関数、DISTINCT
ORDER BY別名が使える
LIMIT件数を切る

これは結果の決まり方（論理的な順序）で、実際の実行計画は DB が最適化して決める。ウィンドウ関数は WHERE・GROUP BY・HAVING のあとに計算されるので、その結果で絞るにはサブクエリか CTE で包む。

SELECT の基本

SELECT DISTINCT u.id, u.name, lower(u.email) AS email
FROM users AS u
WHERE u.status IN ('active', 'trial')
  AND u.created_at >= '2026-01-01'
  AND u.deleted_at IS NULL
  AND u.name LIKE 'Tan%'          -- % は 0 文字以上、_ は 1 文字
ORDER BY u.created_at DESC, u.id   -- 同点の並びを決めるため一意な列も足す
LIMIT 20 OFFSET 40;                -- 3 ページ目（1 ページ 20 件）
やりたいこと書き方メモ
範囲x BETWEEN 1 AND 10両端を含む。日時は >= 開始 AND < 翌日 の半開区間が安全
NULL 判定x IS NULL・x IS NOT NULLx = NULL は常に真にならない
NULL を置き換えCOALESCE(x, 0)最初の非 NULL を返す
値を NULL にNULLIF(x, 0)0 除算よけ: a / NULLIF(b, 0)
条件分岐CASE WHEN x > 0 THEN 'plus' ELSE 'other' ENDどの句の中でも使える
型変換CAST(x AS INTEGER)PostgreSQL は x::int とも書ける
大文字小文字を無視lower(name) LIKE 'tan%'PostgreSQL は ILIKE。MySQL は照合順序次第で最初から無視される
重複を除くSELECT DISTINCT a, b列の組み合わせで判定。PostgreSQL には DISTINCT ON (a) もある

JOIN

結果に出る行A = 左のテーブル（FROM 側）、B = 右のテーブル
INNER JOIN両方に一致する行だけ。JOIN だけでも同じ
LEFT JOINA は全部残し、B が無い行は B の列が NULL
A にだけある行LEFT JOIN … WHERE b.id IS NULL か NOT EXISTS
FULL OUTER JOIN両方を全部残す。MySQL には無い（LEFT と RIGHT を UNION） 
-- 注文と顧客（顧客が消えた注文も残す）
SELECT o.id, o.total, c.name
FROM orders AS o
LEFT JOIN customers AS c ON c.id = o.customer_id
WHERE o.created_at >= '2026-11-01';

-- LEFT JOIN の右側の条件は ON に書く（WHERE に書くと INNER JOIN と同じ結果になる）
SELECT c.id, count(o.id) AS paid_orders
FROM customers AS c
LEFT JOIN orders AS o ON o.customer_id = c.id AND o.status = 'paid'
GROUP BY c.id;

-- 両方のテーブルに同じ名前の列（ここでは order_id）があるなら USING
SELECT * FROM orders JOIN order_items USING (order_id);

-- 全組み合わせ
SELECT * FROM sizes CROSS JOIN colors;

集計

関数返すものメモ
count(*)行数NULL の行も数える
count(col)col が NULL でない行数count(DISTINCT col) で種類の数
sum・avg合計・平均NULL は無視。対象が 0 行だと NULL を返す（COALESCE(sum(x), 0)）
min・max最小・最大文字列・日時にも使える
文字列をつなぐグループ内の値を連結PostgreSQL string_agg(name, ',')・MySQL / SQLite group_concat(name)
 
SELECT customer_id,
       count(*)                                        AS orders,
       sum(total)                                      AS revenue,
       sum(CASE WHEN status = 'paid' THEN 1 ELSE 0 END) AS paid   -- 条件付き集計（どの DB でも動く）
FROM orders
WHERE created_at >= '2026-01-01'   -- 行の条件
GROUP BY customer_id
HAVING sum(total) >= 10000         -- グループの条件
ORDER BY revenue DESC;

-- PostgreSQL・SQLite は FILTER も使える
SELECT count(*) FILTER (WHERE status = 'paid') AS paid FROM orders;

SELECT に書く集計以外の列は GROUP BY に入れる。MySQL は既定（ONLY_FULL_GROUP_BY）でエラーにし、SQLite は通してしまう（どの行の値になるかは決まらない）。PostgreSQL は主キーで GROUP BY すれば同じテーブルのほかの列を書ける。

ウィンドウ関数

行をまとめずに、行ごとに「グループ内での順位・累計・前後の行」を計算する。MySQL 8.0・SQLite 3.25 から使える。

関数(…) OVER (PARTITION BY 区切る列 ORDER BY 並べる列 [フレーム])
関数用途
row_number()1, 2, 3 …（同点でも別の番号）
rank()・dense_rank()同点は同順位。rank は次を飛ばす（1,1,3）、dense_rank は飛ばさない（1,1,2）
lag(x)・lead(x)前の行・次の行の値（前日比など）。lag(x, 1, 0) で既定値
sum(x) OVER (…)累計・移動合計（集計関数はそのままウィンドウ関数になる）
first_value(x)・last_value(x)フレームの最初・最後の値（last_value は下の注意を参照）
ntile(4)4 等分したときの何番目か
 
-- 顧客ごとに最新の注文 1 件（グループごとの上位 N 件）
SELECT *
FROM (
  SELECT o.*,
         row_number() OVER (PARTITION BY customer_id ORDER BY created_at DESC) AS rn
  FROM orders AS o
) AS t
WHERE rn = 1;

-- 日別売上の累計と前日比
SELECT day, sales,
       sum(sales) OVER (ORDER BY day)                 AS running_total,
       sales - lag(sales) OVER (ORDER BY day)         AS diff,
       avg(sales) OVER (ORDER BY day
                        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) AS avg_7d
FROM daily_sales;

ORDER BY を書いたときの既定のフレームは「先頭から今の行（と同じ値の行）まで」。last_value がグループの最後にならないのはこのため。グループ全体にしたいなら ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING を付ける。

CTE（WITH）とサブクエリ

-- 名前を付けた一時的な結果。上から順に読める
WITH monthly AS (
  SELECT customer_id, date_trunc('month', created_at) AS m, sum(total) AS amount  -- date_trunc は PostgreSQL
  FROM orders GROUP BY 1, 2
), ranked AS (
  SELECT *, rank() OVER (PARTITION BY m ORDER BY amount DESC) AS r FROM monthly
)
SELECT * FROM ranked WHERE r <= 3;

-- 再帰 CTE: 木構造（部署・カテゴリ・コメントのスレッド）をたどる
WITH RECURSIVE tree AS (
  SELECT id, parent_id, name, 1 AS depth FROM categories WHERE parent_id IS NULL
  UNION ALL
  SELECT c.id, c.parent_id, c.name, t.depth + 1
  FROM categories AS c JOIN tree AS t ON c.parent_id = t.id
)
SELECT * FROM tree ORDER BY depth;
書き方使いどころ
WHERE EXISTS (SELECT 1 FROM … WHERE …)関連する行が 1 件でもあるか。NOT EXISTS は「無いもの」探しの定番
WHERE id IN (SELECT …)値の一覧に入っているか。NOT IN は NULL に注意（よくある誤解を参照）
(SELECT max(x) FROM …) AS mスカラーサブクエリ。1 行 1 列を返す式として使う
JOIN LATERAL (SELECT … LIMIT 3) AS t ON true外側の行ごとに副問い合わせを回す（行ごとの上位 N 件）。別名（AS t）が要る。PostgreSQL・MySQL 8.0.14 以降
UNION / UNION ALL結果を縦につなぐ。UNION は重複を除く分だけ重い

追加・更新・削除

INSERT INTO users (name, email) VALUES ('Tanaka', 't@example.com'), ('Sato', 's@example.com');
INSERT INTO archive (id, name) SELECT id, name FROM users WHERE deleted_at IS NOT NULL;

UPDATE users SET status = 'inactive', updated_at = CURRENT_TIMESTAMP
WHERE last_login_at < '2026-01-01';

DELETE FROM sessions WHERE expires_at < CURRENT_TIMESTAMP;

UPDATE・DELETE は、先に同じ WHERE で SELECT count(*) して件数を確かめ、トランザクションの中で実行すると戻せる。

UPSERT（あれば更新、なければ追加）と RETURNING

INSERT INTO users (email, name) VALUES ('t@example.com', 'Tanaka')
ON CONFLICT (email) DO UPDATE SET name = EXCLUDED.name   -- EXCLUDED = 入れようとした行
RETURNING id, name;

INSERT INTO tags (name) VALUES ('sql') ON CONFLICT DO NOTHING;

-- 標準 SQL の MERGE（PostgreSQL 15 以降。RETURNING は 17 以降）
MERGE INTO stock AS s
USING incoming AS i ON s.sku = i.sku
WHEN MATCHED THEN UPDATE SET qty = s.qty + i.qty
WHEN NOT MATCHED THEN INSERT (sku, qty) VALUES (i.sku, i.qty);

ON CONFLICT (列) の列には一意制約か一意インデックスが要る。

-- 8.0.19 以降: 入れようとした行に別名を付けて参照する
INSERT INTO users (email, name) VALUES ('t@example.com', 'Tanaka') AS new
ON DUPLICATE KEY UPDATE name = new.name;

-- 重複は無視（ほかのエラーまで警告に変わるので注意）
INSERT IGNORE INTO tags (name) VALUES ('sql');

-- 追加した AUTO_INCREMENT の値
SELECT LAST_INSERT_ID();

MySQL（9.7 LTS まで）には RETURNING と MERGE が無い。古い書き方の VALUES(name) は 8.0.20 で非推奨になった。

-- 3.24 以降。書き方は PostgreSQL とほぼ同じ
INSERT INTO users (email, name) VALUES ('t@example.com', 'Tanaka')
ON CONFLICT (email) DO UPDATE SET name = excluded.name
RETURNING id;            -- RETURNING は 3.35 以降

INSERT OR IGNORE INTO tags (name) VALUES ('sql');
INSERT OR REPLACE INTO kv (k, v) VALUES ('a', 1);   -- 行を消して入れ直す（ほかの列は既定値に戻る）

  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,   -- PostgreSQL の連番（下の表）

よくある誤解

NOT IN (サブクエリ) は NOT EXISTS と同じ結果になる

サブクエリの結果に NULL が 1 つでも混じると、x NOT IN (…) は真にならず 0 件になる（NULL との比較は「不明」になるため）。「無いもの」を探すときは NOT EXISTS を使うか、サブクエリ側で WHERE col IS NOT NULL を付ける。

ORDER BY を書かなくても主キー順や追加順で返ってくる

ORDER BY の無い結果の並びは決まっていない。同じクエリでも実行計画やデータ量で変わる。ページングするときは、同点が出ないよう一意な列（id など）を最後に足す。

count(列) は count(*) と同じ件数になる

count(列) はその列が NULL の行を数えない。行数がほしいなら count(*)。LEFT JOIN で「0 件」を出したいときは、右側の列で count(o.id) と数えるのが正しい。

LEFT JOIN の右テーブルの条件は WHERE に書いてよい

WHERE は JOIN のあとに評価されるので、右側が NULL の行（相手が無い行）が消え、INNER JOIN と同じ結果になる。右側を絞る条件は ON … AND o.status = 'paid' のように ON に書く。

WHERE で SELECT に付けた別名を使える

WHERE は SELECT より先に評価されるので、別名はまだ無い。式をもう一度書くか、サブクエリ・CTE で包む。ORDER BY では別名を使える。
