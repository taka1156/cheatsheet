Colima 使い方

macOS（と Linux）で Docker / containerd / Kubernetes を手軽に動かす CLI のチートシート（v0.10.3 時点）

ざっくり言うと
  • Colima は Lima の Linux VM の中で Docker などを動かし、Mac の docker コマンドから使えるようにする CLI。
  • colima start で VM を作って起動し、Docker コンテキスト colima に自動で切り替える。
  • VM の種類やマウント方式は作成後に変えられないので、変えたいときは colima delete して作り直す。

仕組み

名前の由来は Containers on Lima。Mac 上の docker CLI は、Colima が作った Docker コンテキストを通して VM の中の Docker Engine に話しかける。

Mac（ホスト）docker / kubectl / nerdctl などのクライアント
Docker コンテキスト名前は colima（別プロファイルは colima-名前）。
ソケット ~/.colima/default/docker.sock
Lima VM（Ubuntu）VM の種類: vz（macOS 13 以降の既定）/ qemu / krunkit
dockerdcontainerdk3sincus
マウント既定で $HOME を書き込み可でマウント。ほかの場所は mounts に足す。
ポート転送コンテナが公開したポートは自動で Mac の localhost に転送される（既定は ssh 方式、TCP のみ）。
ホストへの接続コンテナから Mac へは host.docker.internal で届く。

はじめかた

  1. インストールbrew install colima docker。Colima は VM を用意するだけなので、docker クライアント（必要なら docker-compose・docker-buildx・kubectl）は別に入れる。
  2. 起動colima start。初回は VM イメージをダウンロードして作成する。既定は 2 CPU・メモリ 2GiB・ディスク 100GiB。
  3. 使うdocker run hello-world。追加の設定なしで Mac の docker がそのまま使える。
  4. 止めるcolima stop。コンテナやイメージは残り、次の colima start で戻る。

ログイン時に自動で起動したいときは、Homebrew で入れていれば brew services start colima。

コマンド チートシート

プロファイル名を省くと default。-p 名前（--profile）でも指定できる。危険 はデータが消える操作。

コマンドやること
colima startVM を作成（初回）または起動する。すでに起動中なら何もしない
colima start --cpus 4 --memory 8CPU・メモリ（GiB）を指定して起動。止めてから実行すると既存の VM にも反映される
colima start --edit設定ファイル（colima.yaml）をエディタで開いてから起動する
colima start --foregroundフォアグラウンドで動かし続ける（launchd などで管理するとき）
colima stopVM を止める。コンテナ・イメージ・ボリュームは残る
colima stop --force正常終了を待たずに止める。colima list が Broken のときに使う
colima restart止めてから起動し直す（設定ファイルを書き換えたあとなど）
colima delete 危険VM を削除する。v0.9.0 以降、コンテナのデータは別ディスクに残り、次の start で戻る
colima delete --data 危険コンテナ・イメージ・ボリュームのデータも含めてすべて消す
コマンドやること
colima status起動状態・ランタイム・ソケットのパスなどを表示（-e で詳細、-j で JSON）
colima list全プロファイルの状態・CPU・メモリ・ディスク・ランタイム・IP を一覧（ls でも可）
colima start workプロファイル work で別の VM を作って起動する（同時に複数動かせる）
colima stop workプロファイル work を止める
colima clone default work既存のプロファイルを複製して新しいプロファイルを作る
colima versionColima と、中で動くランタイムのバージョンを表示
docker context lsDocker コンテキストの一覧。* が今使っているもの
docker context use colimaColima の Docker に切り替える（Docker Desktop に戻すなら desktop-linux など）
コマンドやること
colima sshVM にログインする
colima ssh -- uname -aVM の中で 1 コマンドだけ実行する。-- で Colima のフラグと区切る
colima ssh-configVM に接続するための SSH 設定を表示（エディタのリモート接続などに使う）
colima ssh -- sudo fstrim -aVM の中で空いたディスク領域を Mac 側に返す（v0.5.0 以降は起動時にも自動で行う）
colima start --network-addressMac から直接届く IP アドレスを VM に割り当てる（macOS のみ。既定はオフ）
colima start --dns 1.1.1.1VM の DNS サーバーを指定する。VM からネットにつながらないときに試す
colima start --mount ~/work:wマウントするディレクトリを指定（:w で書き込み可）。指定すると既定の $HOME の代わりになる
コマンドやること
containerd
colima start --runtime containerdDocker の代わりに containerd で起動する
colima nerdctl -- psVM の中の nerdctl を実行する
colima nerdctl installMac の $PATH に nerdctl のラッパーを置き、nerdctl だけで呼べるようにする
Kubernetes（k3s）
colima start --kubernetesKubernetes（k3s）も一緒に起動し、kubectl のコンテキストを切り替える
colima kubernetes stopKubernetes だけ止める（start・delete・reset もある）
Incus
colima start --runtime incusIncus（コンテナと VM を扱う）で起動する。Mac の incus クライアントから使う
AI モデル（Apple Silicon・macOS 13 以降）
colima start --vm-type krunkitGPU を使える krunkit の VM で起動する（krunkit を別に入れておく）
colima model run gemma3AI モデルを取得して実行する（Docker ランタイムと krunkit が必要）
コマンドやること
colima start --editそのプロファイルの colima.yaml を編集してから起動
colima template新しく作る VM の既定値（テンプレート）を編集する
colima template --printテンプレートのファイルのパスを表示するだけ
colima update中の Docker / containerd だけを最新にする（v0.7.6 以降）
brew upgrade colimaColima 本体を更新する。新しい VM イメージを使うには colima delete → colima start
colima pruneダウンロード済みのイメージなどのキャッシュを消す（-a で Lima の分も）
colima start --verbose詳しいログを出して起動する。起動しない原因を調べるとき

colima start のよく使うオプション

オプション既定値意味
-c
--cpus		2CPU 数
-m
--memory		2メモリ（GiB）
-d
--disk		100コンテナ用ディスク（GiB）。あとから増やせるが減らせない
-r

-t

-a

--mount-typevirtiofs（vz）virtiofs / 9p / sshfs。qemu の既定は sshfs。作成後は変えられない

--mount		$HOMEマウントするディレクトリ。:w で書き込み可、none でマウントなし
-k

--network-addressオフMac から届く IP を VM に割り当てる

--dns		なしVM の DNS サーバー（複数回指定できる）
--envなしVM に渡す環境変数（--env KEY=value）
--port-forwardersshssh（TCP のみ・安定）/ grpc（UDP も可・試験的）/ none

CPU・メモリ・ディスクは、colima stop してから新しい値で colima start すれば変えられる。VM の種類・マウント方式・アーキテクチャは作り直しが必要。

設定ファイル

フラグの代わりに YAML でも設定できる。colima start --edit で開くのが早い。

ファイル中身
~/.colima/default/colima.yamlプロファイル default の設定。別プロファイルは ~/.colima/名前/colima.yaml
~/.colima/_templates/default.yaml新しく作る VM の既定値（colima template で編集）
~/.colima/default/docker.sockDocker のソケット。colima status でも確かめられる
~/.colima/_lima/_config/override.yamlLima の設定を上書きする（上級者向け）

置き場所は $COLIMA_HOME で変えられる。設定していなければ ~/.colima が使われる（~/.colima が無く $XDG_CONFIG_HOME が設定されているときは $XDG_CONFIG_HOME/colima。Linux で両方とも無いときは ~/.config/colima）。

colima.yaml の例

cpu: 4
memory: 8           # GiB
disk: 100           # GiB。増やすのは値を変えて再起動するだけ
runtime: docker
vmType: vz          # 作成後は変えられない
rosetta: true       # Apple Silicon で amd64 イメージを速く
mountType: virtiofs # 作成後は変えられない
mounts:             # 書くと既定の $HOME マウントの代わりになる
  - location: ~/work
    writable: true
  - location: /Volumes/data
    writable: true
network:
  dns: [1.1.1.1]
docker:             # Docker の daemon.json に入る内容
  insecure-registries:
    - myregistry.local:5000
env:
  TZ: Asia/Tokyo

Docker Desktop との共存・ソケット

Colima は起動時に Docker コンテキスト colima を作って既定にするので、Docker Desktop を入れたままでも使える。どちらを使うかは docker context use で切り替える。

コンテキストを見ないツール（一部の IDE やライブラリ）が Cannot connect to the Docker daemon at unix:///var/run/docker.sock と言うときは、どちらかで Colima のソケットを教える。

# 1. 環境変数で指す（シェルの設定ファイルに書く）
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock"

# 2. 既定のパスにリンクを張る（ほかの Docker と衝突することがある）
sudo ln -sf $HOME/.colima/default/docker.sock /var/run/docker.sock

よくある誤解

起動中に colima start --cpus 4 を実行すれば CPU 数が変わる

起動中の colima start は「already running」と出して何もしない。先に colima stop してから新しい値で colima start する。

colima start --vm-type や --mount-type を付け直せば既存の VM も切り替わる

VM の種類とマウント方式は作成時に決まり、あとから変えられない。colima delete してから作り直す（v0.9.0 以降はコンテナのデータは残る）。

colima delete をするとイメージやボリュームもすべて消える

v0.9.0 以降はコンテナのデータを別ディスクに置くので、colima delete では消えず、次の colima start で戻る。すべて消したいときは colima delete --data。

Mac のどのディレクトリでも docker run -v でマウントできる

既定で VM にマウントされるのは $HOME だけ。それ以外（/Volumes/… など）を -v で指定するとエラーにならず空のディレクトリになる。colima.yaml の mounts に足して colima restart する。

Colima を使うには Docker Desktop をアンインストールする必要がある

Docker コンテキストで切り替えるので共存できる。Colima は起動時に自分のコンテキストを既定にする。

docker system prune で消せば Mac のディスクもすぐ空く

VM の中で空いた領域が Mac 側に返るのは次の起動時（v0.5.0 以降）。すぐ返したいときは colima ssh -- sudo fstrim -a。

うまく動かないとき

  1. colima list が BrokenMac の再起動のあとなどに起きる。colima stop --force で Stopped に戻してから colima start。
  2. 起動に失敗するcolima start --verbose でログを見る。Apple Silicon で x86_64 版の Homebrew（と Colima）を使っていないかも確かめる。
  3. 更新したらおかしくなったcolima start debug のように別プロファイルで試し、そちらが動くなら colima delete → colima start で作り直す。
  4. VM からネットにつながらない多くは DNS。colima start --dns 8.8.8.8 --dns 1.1.1.1 を試し、colima ssh -- ping -c4 google.com で確かめる。
