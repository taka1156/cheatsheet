Pagefind 使い方

ビルド済みの静的サイトに、サーバーなしの全文検索を足す（1.6）

ざっくり言うと
  • 静的サイトのビルド後に走らせると、HTML から検索の索引と UI を作って出力フォルダに置くツール。
  • 索引は細かく分かれていて、ブラウザは検索語に必要な分だけを読み込んで WebAssembly で検索する。
  • 開発サーバーではなくビルド結果に対して動かす。日本語は extended 版が要る（npx は既定で extended）。

ビルドから検索まで

1. SSG でビルドHugo・Astro・Eleventy など何でもよいpublic/**/*.html
2. pagefind を実行HTML を読んで索引を作るnpx -y pagefind --site public
3. 出力に検索一式索引のかけら・UI の JS / CSS・wasmpublic/pagefind/
4. ブラウザで検索必要な索引だけを取りに行く。サーバー処理なしimport("/pagefind/pagefind.js")

CI では「ビルド → pagefind → デプロイ」の順にする。public/pagefind/ はビルドのたびに作り直すので、Git には入れない。

はじめかた

  1. UI を置く検索を出したいページ（レイアウト）に次を書く。参照先のファイルは手順 3 で作られる 
    <link href="/pagefind/pagefind-component-ui.css" rel="stylesheet">
<script src="/pagefind/pagefind-component-ui.js" type="module"></script>

<pagefind-modal-trigger></pagefind-modal-trigger>
<pagefind-modal></pagefind-modal>
  2. サイトをビルドする出力フォルダ（例: public/）に HTML ができた状態にする。<html lang="ja"> を付けておく
  3. 索引を作って確かめるnpx -y pagefind --site public --serve。索引を作ったあと、ローカル（多くは :1414）で出力を配信する
  4. ビルドに組み込む"build": "hugo && pagefind --site public" のように、--serve を外してビルドの後ろに足す（npm i -D pagefind で版を固定）

入れ方

方法コマンド・補足
npxnpx pagefind --site public。版の固定は npx pagefind@v1.6.0 …。常に extended 版（中国語・日本語・タイ語の分かち書き入り）
pippython3 -m pip install 'pagefind[extended]' → python3 -m pagefind --site public。pagefind[bin] は小さい標準版で日本語の分かち書きなし
バイナリGitHub Releases の pagefind か pagefind_extended を直接実行。依存なしの単体バイナリ
cargocargo install pagefind --features extended
UI を npm でnpm i @pagefind/component-ui → import '@pagefind/component-ui' と import '@pagefind/component-ui/css'（バンドラーで UI を組み込むとき）

検索 UI

今の推奨は Web Components の Component UI。new PagefindUI() の Default UI は旧方式（legacy）で、新しく作るなら使わない。

要素使いどころ・主な属性
<pagefind-modal-trigger>モーダルを開くボタン。shortcut（既定 mod+k）・hide-shortcut・compact（アイコンだけ）・placeholder
<pagefind-modal>ページの上に重ねて開く検索ダイアログ（幅 640px 以下の画面では全画面）。キーボード操作つき。reset-on-close で閉じたら入力を消す
<pagefind-searchbox>ナビに置く、入力＋ドロップダウンの一体型。show-sub-results（既定は見出し単位の結果を出さない）・max-results・debounce（既定 150ms）・shortcut
要素使いどころ・主な属性
<pagefind-input>検索欄。debounce（既定 300ms）・autofocus・placeholder
<pagefind-results>結果の一覧。見出し単位の結果は既定で出る（hide-sub-results で消す）。show-images・max-results・link-target="_blank"
<pagefind-summary>件数と検索の状態
<pagefind-keyboard-hints>キーボード操作の案内
<pagefind-filter-dropdown filter="tag">1 つのフィルターのドロップダウン。label・single-select・sort="count-desc"
<pagefind-filter-pane>チェックボックスのサイドバー型フィルター
instance="docs"どの要素にも付けられる。同じ名前どうしが状態を共有し、別の名前は独立した検索になる（既定 default）
<pagefind-config> の属性やること
bundle-path索引の場所。既定はスクリプトの場所から自動で決まり、失敗すると /pagefind/
base-url結果のリンクの頭に付ける URL（既定 /）。サブパスに置いたサイト向け
preload最初の検索を待たずにすぐ読み込む
faceted検索語が空でも全件を出し、フィルターの変更ですぐ絞る（カタログ型）。preload と併用
sort="date:desc"関連度ではなくソートキーで並べる
excerpt-length抜粋の長さ（語数、既定 30）
highlight-param結果のリンクに検索語のクエリを付ける（遷移先で pagefind-highlight.js を使ってハイライト）
lang検出した言語を上書きする
no-workerWeb Worker を使わずメインスレッドで動かす
// 初期化（省略可。入力欄のフォーカス時に呼ぶと速く感じる）
const pagefind = await import("/pagefind/pagefind.js");
await pagefind.options({ bundlePath: "/docs/pagefind/" }); // init より前
pagefind.init();

// 検索：まず ID だけ返る。中身は 1 件ずつ data() で取る
const search = await pagefind.search("static");
const top5 = await Promise.all(search.results.slice(0, 5).map(r => r.data()));
// → { url, excerpt（<mark> 入り）, meta: { title, image }, sub_results: [...] }

// 入力のたびに呼ぶなら（新しい呼び出しがあると古い方は null）
const s = await pagefind.debouncedSearch(term, {}, 300);
if (s === null) return;

// フィルター・ソート
const filters = await pagefind.filters();         // { tag: { Go: 3, ... } }
await pagefind.search("static", { filters: { tag: "Go" }, sort: { date: "desc" } });
await pagefind.search(null, { filters: { tag: "Go" } }); // 検索語なしで絞るだけ

excerpt はエスケープ済みで innerHTML に入れてよい。meta と content は生の値なので自分でエスケープする。

data-pagefind 属性（索引の作り方を HTML で決める）

書き方やること
<main data-pagefind-body>索引に入れる範囲を本文に絞る（既定は <body> 全体）。サイトのどこかに 1 つでもあると、付いていないページは索引から外れる
data-pagefind-ignoreその要素と子を索引から外す。中の meta・filter とタイトル・画像の検出は生きる（値 index と同じ）
data-pagefind-ignore="all"中の meta・filter も含めて、何も拾わない
data-pagefind-meta="title"要素の文字をメタデータとして結果に返す（メタデータも検索対象）
data-pagefind-meta="image[src]"属性の値を取る。"image[src], image_alt[alt]" とカンマで並べられる
data-pagefind-meta="date:2026-11-27"値をその場で書く（並べるときは最後に 1 つだけ）
data-pagefind-default-meta="image[content]"ほかで値が取れなかったときの既定値（OGP 画像など）
data-pagefind-filter="tag"フィルターの値を付ける。1 ページに複数の値を持てる。tag[data-x]・tag:Go も可
data-pagefind-sort="date"ソートキーを付ける。全部が数値なら数値順、1 つでも違えば文字順。キーの無いページはそのソートの結果から消える
data-pagefind-weight="2"その部分の重み（0.0〜10.0、既定 1）。二乗で効くので 2 で約 4 倍
id="x" data-pagefind-title="名前"見出し以外の要素をページ内の結果（sub result）の区切りにする（1.6 から）
data-pagefind-index-attrs="title,alt"要素の属性の値を本文として索引に入れる

該当する属性はありません。

自動のメタデータ: title は最初の h1、image・image_alt は h1 の後の最初の img。見出しの重みは h1 7 〜 h6 2、ほかは 1。<nav>・<footer>・<script>・<form> などは最初から索引に入らない。any・all・none・not はフィルター名に使えない。

CLI オプション

CLI フラグ・環境変数・設定ファイルのどれでも書ける。優先は CLI ＞ 環境変数 ＞ 設定ファイル。設定ファイルは実行したフォルダの pagefind.toml・pagefind.yml・pagefind.yaml・pagefind.json。

CLI（設定キー）やること
--site（site）必須。ビルド済みサイトのフォルダ
--serve索引を作ったあと、そのフォルダを配信して確かめる
--output-subdir（output_subdir）出力先をサイト内のフォルダ名で（既定 pagefind）
--output-path（output_path）出力先を作業フォルダからのパスで（output-subdir より優先）
--glob（glob）読む HTML の glob（既定 **/*.{html}）。一部のページだけを索引にする
--exclude-selectors（exclude_selectors）テンプレートを変えずに要素を外す。CLI では 1 つだけ（カンマ区切りの CSS セレクターは可）、複数は設定ファイルの配列で
--root-selector（root_selector）文書の根にする要素（既定 html）。外側の meta・filter も拾わなくなる
--force-language（force_language）言語の検出をやめ、全ページを 1 つの言語の索引にする（例: ja）
--include-characters（include_characters）落とさない記号（例: "<>$"）。シェルで化けるなら設定ファイルに書く
--max-fragments（max_fragments）出力ファイル数の上限（言語ごと）。ファイル数に制限のあるホスティング向け（1.6 から）
--keep-index-url結果の URL に index.html を残す
--write-playground索引を調べる playground を pagefind/playground/ に書き出す（--serve 中は常に使える）
--verbose / --quiet / --silent / --logfileログの量と出力先
# pagefind.yml（npx pagefind だけで動く）
site: public
exclude_selectors:
  - "#toc"
  - ".code-copy"

環境変数は PAGEFIND_ ＋ 大文字（例: PAGEFIND_SITE=public npx pagefind）。

日本語・多言語

  • <html lang> ごとに別の索引ができ、ブラウザは表示中のページと同じ言語の索引だけを検索する。lang が無いと結果 ID の頭が unknown になる
  • 日本語は語幹処理（stemming）は無く、空白の無い文の分かち書きで単語に分ける。分かち書きは extended 版だけ（npx は既定で extended、pip は [extended] を付ける）
  • 1.6 で分かち書きが ICU4X に変わり、ブラウザ側（Intl.Segmenter）との分け方の差が小さくなった
  • 連続した語をそのまま探すなら "…" で囲む（フレーズ検索）

置き場所で困ったら

症状対処
サブパスに置いたらリンクが壊れる<pagefind-config base-url="/docs/">（JS API は baseUrl）。索引の場所がずれるなら bundle-path
CSP で WebAssembly が止まるscript-src 'wasm-unsafe-eval' を足す。Worker が止まるなら worker-src 'self' blob: か no-worker
デプロイのファイル数の上限に当たる--max-fragments
サーバーの gzip 設定不要。Pagefind が自分で圧縮して出力する

よくある誤解

検索のためにサーバーか外部の検索サービスが要る

索引も検索の処理も静的ファイルで、ブラウザの中で動く。--serve は確認用に出力フォルダを配信するだけで、本番には要らない。

hugo serve などの開発サーバーでも検索を試せる

Pagefind が読むのはビルドした出力。開発サーバーには /pagefind/ が無いので、ビルドして pagefind --site public --serve で確かめる。

data-pagefind-body は付けたページにだけ効く

サイトのどこかに 1 つでもあると、付いていないページはすべて索引から外れる。トップページなども検索に出したいなら、そこにも付ける。

data-pagefind-body の外にある meta や filter は無視される

メタデータとフィルターは本文の範囲の外（<head> など）でも拾われる。拾わせたくないなら data-pagefind-ignore="all" か --root-selector。

pip install pagefind[bin] でも日本語のページは検索できる

標準版には日本語の分かち書きが無く、空白の無い文がうまく単語に分かれない。pagefind[extended] か npx を使う。
