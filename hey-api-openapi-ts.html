Hey API openapi-ts 使い方

@hey-api/openapi-ts で OpenAPI 定義から TypeScript の型・SDK・HTTP クライアントを生成する（v0.99 時点）

ざっくり言うと
  • OpenAPI 定義（ファイル・URL）から、型（types.gen.ts）と型付きの API 関数（sdk.gen.ts）を生成する CLI。
  • 何を生成するかはプラグインで決まり、既定は型＋SDK＋Fetch クライアントで、Zod や TanStack Query も足せる。
  • まだ 0.x で破壊的変更が多いので版を固定し、生成物は手で直さず設定と定義の側を変える。

生成の流れ

inputopenapi.yaml・URL・API レジストリ
parser定義を読み込み、フィルターや変換をかける
plugins型・SDK・クライアント・Zod など、1 プラグイン＝生成物 1 種類
outputsrc/client/ に *.gen.ts を書き出す

インストールと実行

npx @hey-api/openapi-ts -i ./openapi.yaml -o src/client

Node.js 22 系以上が必要（0.99 の engines は >=22.18.0）。0.91 から ESM のみ。

# 0.x なので完全一致で固定する（-E = --save-exact）
npm install -D -E @hey-api/openapi-ts

// package.json
"scripts": {
  "openapi-ts": "openapi-ts"
}

npm run openapi-ts    # openapi-ts.config.ts を読んで生成
import { createClient } from '@hey-api/openapi-ts';

await createClient({
  input: './openapi.yaml',
  output: 'src/client',
});
npm install -D @hey-api/vite-plugin

// vite.config.ts（Vite 5〜8）
import { heyApiPlugin } from '@hey-api/vite-plugin';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [
    heyApiPlugin({
      config: { input: './openapi.yaml', output: 'src/client' },
    }),
  ],
});

CLI オプション

オプション意味
-i, --inputOpenAPI 定義（パス・URL）。スペース区切りで複数（例 -i a.yaml b.yaml）
-o, --output出力フォルダ。スペース区切りで複数
-c, --clientHTTP クライアントのプラグイン（例 @hey-api/client-axios）
-p, --plugins使うプラグイン（スペース区切りで複数）
-f, --file設定ファイルのパス
-w, --watch定義の変更を監視して再生成（間隔 ms を指定可。監視できるのは URL の入力だけ）
--dry-runファイルを書かずに実行
-d, --debug / -s, --silentデバッグログ / 出力を抑える
-l, --logs / --no-log-fileログの出力先 / ログファイルを作らない

設定ファイル

プロジェクトのルートに openapi-ts.config.ts（.mjs・.cjs・.js も可）を置く。

// openapi-ts.config.ts
import { defineConfig } from '@hey-api/openapi-ts';

export default defineConfig({
  input: './openapi.yaml',          // パス・URL・'hey-api/backend' のようなレジストリ指定
  output: {
    path: 'src/client',
    postProcess: ['prettier'],      // 生成後に整形（'biome:format'・'oxfmt'・'eslint' なども可）
  },
  plugins: [
    '@hey-api/typescript',          // types.gen.ts
    '@hey-api/sdk',                 // sdk.gen.ts
    '@hey-api/client-fetch',        // client.gen.ts（既定のクライアント）
  ],
});
// 認証が要る URL から取る
input: {
  path: 'https://api.example.com/openapi.json',
  fetch: { headers: { Authorization: 'Bearer xxx' } },
  watch: true,                      // 開発中に URL を監視して再生成
},

自己署名証明書の HTTPS から読むときは、環境変数 NODE_TLS_REJECT_UNAUTHORIZED=0 が要る（開発時のみ）。

キー意味
path出力フォルダ
postProcess生成後に走らせるツール。prettier・biome:format・biome:check・oxfmt・oxlint・eslint
entryFilefalse で index.ts を作らない
fileName.suffixファイル名の接尾辞（既定 .gen、null で無し）
module.extensionimport に付ける拡張子（Node の ESM なら '.js'）
sourcetrue で入力定義のコピー source.json も出力
 
// 定義ごとに別フォルダへ（入力と出力の配列を同じ長さに）
export default defineConfig({
  input: ['./foo.yaml', './bar.yaml'],
  output: ['src/foo', 'src/bar'],
});

// 1 つにまとめる（出力は 1 つ）
export default defineConfig({
  input: ['./foo.yaml', './bar.yaml'],
  output: 'src/client',
});

// 設定ごと分けるなら配列で export する
export default defineConfig([
  { input: './foo.yaml', output: 'src/foo' },
  { input: './bar.yaml', output: 'src/bar', plugins: ['zod'] },
]);

生成されるファイル

src/client/出力フォルダ。手で編集しない（再生成で消える）
├ types.gen.tsスキーマ・リクエスト・レスポンスの型。型だけなのでバンドルに残らない
├ sdk.gen.tsoperation ごとの関数（operationId から名前が付く）
├ client.gen.tsSDK が使う既定の client インスタンス
├ client/ ・ core/HTTP クライアント本体。定義に依存しない土台
└ index.ts型と SDK の再 export（output.entryFile: false で作らない）

生成したクライアントを使う

import { addPet, getPetById } from './client/sdk.gen';

// 引数は path・query・header・body に分けて渡す（paramsStructure: 'grouped' が既定）
const { data, error, response } = await getPetById({
  path: { petId: 1 },
});
if (error) {
  console.error(response?.status, error);   // error は定義の 4xx/5xx の型
} else {
  console.log(data.name);                   // data は 2xx の型
}

// 例外を投げさせて data だけ受け取る
const { data: pet } = await addPet({
  body: { name: 'Fluffy' },
  throwOnError: true,
});

既定（throwOnError: false）では HTTP エラーでも例外にならず、戻り値の error に入る。

import { client } from './client/client.gen';

client.setConfig({
  baseUrl: 'https://api.example.com',
  auth: () => localStorage.getItem('token') ?? undefined,  // securitySchemes がある operation にだけ付く
});

// 1 回だけ別の設定で呼ぶ
await getPetById({ path: { petId: 1 }, baseUrl: 'https://staging.example.com' });
// openapi-ts.config.ts
plugins: [
  { name: '@hey-api/client-fetch', runtimeConfigPath: '../hey-api.ts' },
],

// src/hey-api.ts（出力フォルダからの相対パスで解決される: 0.97〜）
import type { CreateClientConfig } from './client/client.gen';

export const createClientConfig: CreateClientConfig = (config) => ({
  ...config,
  baseUrl: import.meta.env.VITE_API_URL,
});

setConfig() より前にリクエストが走る心配がない。client.gen.ts が初期化時にこの関数を呼ぶ。

import { client } from './client/client.gen';

const id = client.interceptors.request.use((request, options) => {
  request.headers.set('X-Request-Id', crypto.randomUUID());
  return request;
});
client.interceptors.response.use((response) => {
  if (response.status === 401) location.href = '/login';
  return response;
});
client.interceptors.request.eject(id);   // 外す（ID か関数の参照で）

主なプラグイン

文字列で名前だけ書くか、{ name, ...options } で設定付きで書く。同じプラグインを 2 回書くと設定はマージされる（0.99〜）。

プラグイン生成物・主なオプション
@hey-api/typescripttypes.gen.ts。enums: 'javascript' で enum を実行時のオブジェクトとしても出す（既定 false は型だけ）
@hey-api/sdksdk.gen.ts。operations.strategy: 'flat'（既定・関数、tree-shaking 可）／'single'（クラス）、paramsStructure: 'flat' で引数を 1 階層に、validator・transformer
@hey-api/schemasschemas.gen.ts。定義の JSON Schema をそのまま値として出す（フォーム生成などに）
プラグイン使う場面
@hey-api/client-fetch既定。Fetch API の薄いラッパー
@hey-api/client-axiosAxios を使っている（axios が別途必要）
@hey-api/client-nextNext.js の fetch 拡張（キャッシュ・revalidate）を使う
@hey-api/client-nuxtNuxt の $fetch・useFetch を使う
@hey-api/client-ofetch / @hey-api/client-kyofetch / ky を使う
@hey-api/client-angularAngular の HttpClient を使う
 
plugins: [
  { name: '@hey-api/sdk', validator: 'zod', transformer: true },
  { name: '@hey-api/transformers', dates: true },   // 日付文字列を Date に変換
],
プラグイン生成物・用途
zodzod.gen.ts（zPet など）。SDK の validator に指定すると実行時に検証する
valibotvalibot.gen.ts（vPet など）。Zod より小さい
@hey-api/transformerstransformers.gen.ts。dates: true で format: date-time を Date に

検証は実行時のコストがかかるので既定では無効。validator: { request: 'zod' } のように片方だけにもできる。

plugins: ['@tanstack/react-query'],   // vue-query・svelte-query・solid-query なども

// 使う側
import { useQuery, useMutation } from '@tanstack/react-query';
import { getPetByIdOptions, addPetMutation } from './client/@tanstack/react-query.gen';

const { data } = useQuery(getPetByIdOptions({ path: { petId: 1 } }));
const mutation = useMutation(addPetMutation());

Vue 向けの @pinia/colada、モック用の msw などもある（SWR は公式ドキュメント上は計画中。0.99 には文書化されていない swr プラグインが含まれている）。

導入の手順

  1. 定義を用意するoperationId を全 operation に付けておく（無いとパスとメソッドから関数名が作られ、読みにくい）。定義の書き方は Swagger 使い方
  2. インストールして設定を書くnpm i -D -E @hey-api/openapi-ts と openapi-ts.config.ts
  3. 生成するnpm run openapi-ts。CI では生成物との差分が無いことを確かめるか、ビルド前に毎回生成する
  4. クライアントを設定するbaseUrl・auth を setConfig() か runtimeConfigPath で入れる
  5. アップグレードは移行ノートを読んでから0.x のマイナー更新でも破壊的変更がある。版を上げたら再生成して型エラーを確かめる

よくある誤解

生成された .gen.ts を直接直せば済む

次の生成で上書きされて消える。名前や構造を変えたいときはプラグインのオプション（operations.nesting など）か、入力側（定義・parser の設定）で直す。

SDK 関数は HTTP エラーのときに例外を投げる

既定では投げず、{ data, error, request, response } の error に入れて返す。例外にしたいときは呼び出しごとか client.setConfig() で throwOnError: true にする。

型を生成すれば実行時のレスポンスも型どおりだと保証される

生成されるのは TypeScript の型だけで、実行時には確かめない。サーバーが定義と違う値を返す可能性があるなら、validator: 'zod' などで実行時の検証を有効にする。

0.x でもマイナー更新なら ^ で自動的に上げて大丈夫

公式も「初期開発中なので版を完全に固定する」よう勧めている。0.96 で Node 20 の打ち切り、0.91 で CommonJS の打ち切りなど、マイナー版で破壊的変更が入る。
