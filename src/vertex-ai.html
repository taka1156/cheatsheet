Vertex AI（Gemini Enterprise Agent Platform）使い方

Google Gen AI SDK（google-genai 3.x）で Gemini を、AnthropicVertex で Claude を呼ぶ。名前の対応・認証・ロケーション・エージェントのデプロイまで

ざっくり言うと
  • Google Cloud の生成 AI 基盤で、2026 年 4 月に Gemini Enterprise Agent Platform へ改名された（API は同じ）。
  • Gemini は Gen AI SDK の enterprise=True、Claude は AnthropicVertex から、ADC の認証で呼ぶ。
  • 旧 vertexai SDK の生成 AI モジュールは削除済み。古い記事のコードは Gen AI SDK に読み替える。

名前の対応（2026-04 の改名）

Google Cloud Next '26（2026-04-22）で Vertex AI は Gemini Enterprise Agent Platform（略して Agent Platform）になった。中身はそのまま引き継がれ、コード・API・ログには旧名が残っている。

旧名新名
Vertex AI PlatformGemini Enterprise Agent Platform
Vertex AI APIAgent Platform API（サービス名は aiplatform.googleapis.com のまま）
Vertex AI StudioAgent Studio
Vertex AI Model GardenAgent Platform Model Garden
Vertex AI Agent EngineAgent Runtime（API のリソース名は reasoningEngines のまま）
Vertex AI Agent BuilderAgent Platform に統合

IAM ロール roles/aiplatform.user、gcloud の gcloud ai …、SDK の引数 vertexai=True なども旧名のまま使える。

セットアップ

  1. API を有効にするgcloud services enable aiplatform.googleapis.com（課金を有効にしたプロジェクトで）
  2. 権限を付ける呼び出す人・サービスアカウントに roles/aiplatform.user を付ける
  3. 手元の認証（ADC）gcloud auth application-default login。Cloud Run・GKE などでは付けたサービスアカウントが自動で使われる
  4. SDK を入れるPython pip install --upgrade google-genai・Node.js npm install @google/genai・Go go get google.golang.org/genai
  5. 環境変数下の 3 つを入れておけば、コードは genai.Client() だけで済む
export GOOGLE_GENAI_USE_ENTERPRISE=true      # 旧名 GOOGLE_GENAI_USE_VERTEXAI も効く
export GOOGLE_CLOUD_PROJECT=my-project
export GOOGLE_CLOUD_LOCATION=global

試すだけなら、Google Cloud のプロジェクトなしで使える Express mode の API キーもある（使える機能は一部）。

Gemini を呼ぶ

from google import genai
from google.genai import types

client = genai.Client(enterprise=True, project="my-project", location="global")

res = client.models.generate_content(
    model="gemini-3.8-flash",
    contents="SQL の LEFT JOIN を一文で説明して",
    config=types.GenerateContentConfig(
        system_instruction="日本語で簡潔に答える",
        max_output_tokens=1024,
        temperature=0.2,
    ),
)
print(res.text)
print(res.usage_metadata)          # 入出力のトークン数

# ストリーミング
for chunk in client.models.generate_content_stream(model="gemini-3.8-flash", contents="短い物語を"):
    print(chunk.text, end="")

# 会話（履歴を SDK が持つ）
chat = client.chats.create(model="gemini-3.8-flash")
chat.send_message("こんにちは")
print(chat.send_message("さっき何て言った？").text)
import { GoogleGenAI } from '@google/genai';

const ai = new GoogleGenAI({ enterprise: true, project: 'my-project', location: 'global' });

const res = await ai.models.generateContent({
  model: 'gemini-3.8-flash',
  contents: 'SQL の LEFT JOIN を一文で説明して',
  config: { systemInstruction: '日本語で簡潔に答える', maxOutputTokens: 1024 },
});
console.log(res.text);

const stream = await ai.models.generateContentStream({ model: 'gemini-3.8-flash', contents: '短い物語を' });
for await (const chunk of stream) process.stdout.write(chunk.text ?? '');

ブラウザからは enterprise: true・project・location は使えない（Express mode の API キーだけ）。

PROJECT=my-project; LOCATION=global; MODEL=gemini-3.8-flash
curl -X POST \
  -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  -H "Content-Type: application/json" \
  "https://aiplatform.googleapis.com/v1/projects/$PROJECT/locations/$LOCATION/publishers/google/models/$MODEL:generateContent" \
  -d '{"contents":[{"role":"user","parts":[{"text":"こんにちは"}]}]}'
# ストリーミングは :streamGenerateContent
# リージョンを指定するときのホストは https://{LOCATION}-aiplatform.googleapis.com

よく使う API（Python の client. 以下）

メソッド用途メモ
models.generate_contentテキスト・画像・PDF・動画を入れて生成GCS のファイルは types.Part.from_uri(file_uri="gs://…", mime_type=…)
models.generate_content_streamストリーミング生成非同期版は client.aio.models…
chats.create複数ターンの会話send_message・send_message_stream
models.count_tokensトークン数を数えるcompute_tokens は Agent Platform 側だけ
models.embed_content埋め込みベクトルモデルは gemini-embedding-2 など。output_dimensionality で次元を減らせる
caches.create長いプロンプトのコンテキストキャッシュ作った名前を config.cached_content に渡す
batches.createバッチ推論入力は bq://… か gs://…（Agent Platform の場合）
tunings.tune教師ありファインチューニング学習データは GCS の JSONL

ファイルのアップロード（client.files）は Gemini Developer API だけの機能。Agent Platform では GCS に置いて URI で渡す。

config でよく使うもの（types.GenerateContentConfig）

キー用途
system_instructionシステムプロンプト
max_output_tokens・temperature・top_p・stop_sequences出力の長さ・ばらつき・停止語
response_mime_type="application/json" ＋ response_json_schemaJSON Schema に沿った出力（Pydantic のモデルを response_schema に渡してもよい）。プロンプトに同じ例を重ねて書かない
tools=[関数]関数呼び出し。Python の関数を渡すと SDK が自動で呼んで結果を返す（止めるなら automatic_function_calling で disable=True）
tools=[types.Tool(google_search=types.GoogleSearch())]Google 検索でのグラウンディング
thinking_config思考（推論）の量の調整。指定できる値はモデルごとに違う
safety_settings有害カテゴリごとのブロックのしきい値

ロケーションとモデル

locationホスト使いどころ
globalaiplatform.googleapis.com公式のクイックスタートの既定。空いているリージョンに回るので混雑に強い。データの置き場所を縛れない
us・euマルチリージョンのエンドポイント米国内・EU 内に処理を留めたいとき（使えるモデルは限られる）
asia-northeast1 など{location}-aiplatform.googleapis.com特定のリージョンに留めたいとき。モデルごとに対応リージョンが違う

モデル ID は入れ替わりが速いので、使う前に「Google models」のページと Model Garden で確かめる。2026-11 時点の GA の例: Gemini 4 系（gemini-4-argon など）、Flash 系の主力 gemini-3.8-flash、軽量な Flash-Lite 系。

Claude を呼ぶ（Anthropic SDK）

Claude は Model Garden のパートナーモデル（MaaS）として提供される。Model Garden のモデルカードで有効にしてから、Anthropic SDK の Vertex 用クライアントで呼ぶ。

# pip install -U "anthropic[vertex]"
from anthropic import AnthropicVertex

client = AnthropicVertex(project_id="my-project", region="global")   # "us"・"eu"（マルチリージョン）も可
msg = client.messages.create(
    model="claude-opus-5-5",       # Agent Platform での ID（日付の付かない形）
    max_tokens=1024,
    messages=[{"role": "user", "content": "こんにちは"}],
)
print(msg.content[0].text)
# REST: Messages API とほぼ同じ本文を :rawPredict（ストリーミングは :streamRawPredict）に送る
curl -X POST -H "Authorization: Bearer $(gcloud auth print-access-token)" -H "Content-Type: application/json" \
  "https://aiplatform.googleapis.com/v1/projects/my-project/locations/global/publishers/anthropic/models/claude-opus-5-5:rawPredict" \
  -d '{"anthropic_version":"vertex-2023-10-16","max_tokens":256,"messages":[{"role":"user","content":"こんにちは"}]}'

新しい Claude は個別リージョンでは呼べず、global か us・eu だけ。本文では model を書かず URL に入れ、anthropic_version: "vertex-2023-10-16" を付ける。Anthropic 本家の Files API・Message Batches API など、Google 側では使えない機能がある。

エージェント（ADK と Agent Runtime）

pip install google-adk
adk create my_agent                     # ひな形（agent.py に Agent を書く）
adk web                                 # ブラウザで試す（adk run なら端末で）
adk deploy agent_engine my_agent --project=my-project --region=us-central1   # Agent Runtime へ
# SDK から載せる（Agent Platform SDK 2.0.1 以降。旧 vertexai.agent_engines の置き換え）
# pip install "google-cloud-agentplatform[adk,agent_engines]"
import agentplatform
client = agentplatform.Client(project="my-project", location="us-central1")
remote = client.runtimes.create(agent=local_agent, config={"staging_bucket": "gs://my-bucket"})
部品何をするか
ADK（Agent Development Kit）エージェントを書くオープンソースのフレームワーク。Python・Java・Go など
Agent Runtimeエージェントをホストするマネージド実行環境（旧 Agent Engine）。Sessions・Memory Bank・Code Execution も付く
Agent Studioコンソールでプロンプトやモデルを試す画面（旧 Vertex AI Studio）
Agent Identity・Registry・Gatewayエージェントの ID、一覧の管理、通信の出入り口（統制のための部品）

Gemini Developer API との違い

どちらも同じ Gen AI SDK で呼べ、クライアントの作り方だけが違う。

Gemini Developer API（AI Studio）Agent Platform（旧 Vertex AI）
クライアントgenai.Client(api_key=…)genai.Client(enterprise=True, project=…, location=…)
認証API キーIAM（ADC・サービスアカウント）。Express mode なら API キー
エンドポイントgenerativelanguage.googleapis.comaiplatform.googleapis.com（またはリージョン）
向いている場面個人・試作。Google Cloud の設定なしで始めたいGoogle Cloud 上の本番。IAM・VPC Service Controls・リージョン指定・BigQuery 連携が要る
片方だけの機能files（アップロード）などcompute_tokens、GCS・BigQuery 入力のバッチなど

よくある誤解

Vertex AI は終了したので、別のサービスへ移行しなければならない

2026 年 4 月の変更は名前の変更と機能の統合で、API（aiplatform.googleapis.com）、IAM ロール、既存のコードはそのまま動く。新しい機能は Agent Platform の名前で出るので、ドキュメントは新しい名前で探す。

Gemini は vertexai.generative_models の GenerativeModel で呼ぶ

Vertex AI SDK の生成 AI モジュールは 2025-06-24 に非推奨になり、2026-06-24 で削除された。Gemini は Google Gen AI SDK（google-genai）で呼ぶ。エージェント用の機能も google-cloud-agentplatform に分かれた。

location は us-central1 にしておくのが基本

今の公式クイックスタートの既定は global。リージョンを縛る必要があるときだけ us・eu や個別のリージョンを選び、そのモデルが対応しているかを確かめる。
